# V4 集成审核与改进方向

本次将队友 `agv_modeling_integrated_v4` 中有效的业务与建模变化，接入已有模块化项目。V4 的主要价值是补全仓库规则，并未提供比现有 SIPP、联合后缀修复更强的调度算法。原目录、重复网页和生成结果没有整体复制，原始文件保持原样。

集成版本通过113项测试和54次同规则配对运行。新规则能够安全执行；现有优化算法对 V4 综合分数的收益较小且有退化，因此本次不将“支持 V4”表述为“全面优于距离贪心”。逐次数据、配置、源码哈希和精选轨迹见 [`results/v4/`](../results/v4/)。

## 1. 有效差异与处理决定

| V4 内容 | 集成后的职责位置 | 审核决定与含义 |
|---|---|---|
| 背靠背货架、独立上下面、面/货位/层标识、唯一外侧取货位 | `warehouse/layout.py`、`warehouse/rules.py`、`domain.py` | 接纳，消除两侧货架资源混淆，保留可解释标识 |
| 层数与装货时长 `2×层数`；同面同货位最高已释放层优先 | `warehouse/rules.py`、`simulation.py`、`evaluation/validation.py` | 接纳为建模假设，派单、执行、验解三处共同约束 |
| D 站仅用于本订单卸货，不能穿行、提前占位或卸货后滞留 | `planning/astar.py`、`sipp.py`、`pickup.py`、独立验解器 | 接纳；A* 与 SIPP 使用一致的终点角色语义 |
| 1–10辆车、五种尺寸、作业通道宽度、柱体和设备 | `warehouse/layout.py`、CLI、现有网页 | 接纳，保留具体障碍几何及输入检查 |
| 无固定截止时刻，按完成/停滞终止 | `domain.py`、在线驱动、`simulation.py` | CLI 支持 `horizon=None`；网页继续施加有限资源上限 |
| 归一化时间/响应/里程综合评分 | `evaluation/objective.py` | 接纳为离线评价；参考基线和分母可复核，不输入在线策略 |
| 原扁平源码、原时空 A* 与锁定预约路线 | 现有 `planning/`、`dispatch/` | 保留可比较的基线行为，复用现有工程边界与 SIPP/联合修复 |
| 原网页服务与文档片段 | 现有 `web/` 与本报告 | 采用有效控件和展示信息，保留已有 Host/Origin、请求体、并发与超时限制；不沿用“各层服务相同”等过时说明 |

V4 层约束按**已经释放**的订单判断。高层任务尚未发布时，低层可以接单；之后发布的高层不会抢占已接低层。同一面在上一订单装货结束后释放，背靠背的另一面独立。这里的装货规则、权重和能耗系数均是课程模型假设，未经现场测量校准。

## 2. 原测试通过后仍需修复的问题

队友原版71项测试全部通过。本次审核增加了跨模块反例，发现并修复以下问题；“原测试通过”与“所有业务合同均可靠”需要分开判断。

| 问题与反例 | 修复 | 对应回归覆盖 |
|---|---|---|
| 输出记录删去可选 `shelf` 字段后，验解器可能漏查同面接单互斥；装货区间不重叠仍可掩盖过早承诺 | 通过 `task_id` 从不可变任务输入恢复货架资源，并审计接单时刻与层顺序 | `test_v4_execution.py` 的缺少可选货架元数据反例 |
| `service_axis='any'` 与严格 D 站等元数据混用时，原序列化条件可能丢掉规则与参考信息，往返后语义改变 | 明确 legacy/V4 profile；扩展字段必须属于完整受支持的 V4 规则，拒绝混合或未知规则；合法输入无损往返 | `test_v4_domain.py` 的 profile、元数据及序列化测试 |
| 最早可卸货的到达时刻结束后，唯一出口恰好被占用；原组合过程直接无解，延迟一拍到达却可行 | 为交付段增加最早到达约束；出口不可行时，最多尝试8次延迟到达，A* 与 SIPP 一致 | `test_v4_execution.py` 的卸货后立即退出与延迟到达反例 |

第三项是小范围的规划改进，收益在可行性反例上得到验证。八次重试有明确上限，仍可能错过更晚才可行的路径，不能据此声称全程完备或全局最优。正式配对中的基线和优化算法都使用该修复，实验表比较的是修复后各策略，不能从表中单独归因出重试带来的平均收益。

安全边界仍包括：顶点和逆向边避碰、装卸连续且开始后不可中断、执行前缀不变、锁定任务归属不变、完整未来后缀审计通过后才原子提交。V4 正式测试还覆盖动态未来订单不泄漏、同面批量接单原子拒绝、严格 D 站 A*/SIPP 差分、无截止与停滞终止、伪造评分及 CLI/HTTP 入口。

## 3. 评分口径与实验设计

采用 V4 给定的评价口径，分数越低越好：

```text
F = 0.5 × T/Tref + 0.3 × R/Rref + 0.2 × D/Dref
T = 最后一个订单卸货完成时刻
R = 平均（卸货完成时刻 − 订单发布时间）
D = 全部执行移动步数，包含卸货后的回库
```

最终仿真时间还可能包含最后回库，不等于 `T`。`0.05×D` 只用于展示能耗代理，未另加第四个目标。只有执行可行、全部完成且同场景参考基线成功时，综合分数才有效。普通非空场景的基线为1；失败不会被删去后装作成功样本，也不会通过少完成订单来获得可比低分。

参考策略固定为**经过本次规则修复的分层距离贪心＋预约时空 A***，无联合重规划；对完整序列化场景独立计算和验解。场景 profile 标识为 `math-v4-integrated`，本次评分实现标识为 `math-v4-reviewed-v1`。结果内的参考策略标识保留为 `per_face_layer_aware_distance_greedy_service2l_v2`，其实际实现包含本次交付退出修复。评分分母及未来订单只用于离线评价，不出现在在线观察、派单或候选特征中。

正式实验为3类场景×6个种子×3种策略，共54次，全部完成且通过独立验解。每类场景在各策略之间使用完全相同的输入和哈希；种子为0–5，场景均为 V4 小尺寸、三层货架、无固定截止。

| 场景族 | 订单与车辆 | 额外条件 |
|---|---|---|
| `static_layers` | 18单、4车 | 静态已知订单、分层装货 |
| `dynamic_equipment` | 24单、6车 | 动态突发到达、柱体与设备 |
| `dynamic_shared` | 24单、6车 | 动态不规则到达、共享 D 站 |

`baseline` 是上述固定参考；`sipp_budget` 使用 SIPP、拥堵关联候选和最多6次联合修复尝试；`sipp_matching` 在此基础上采用当前批次最小代价匹配。匹配以当前代价为目标，不能推导为全局最优派单。现有 `sipp_learned` 来自旧规则训练，本次未用它作 V4 正式对照，也未重新训练。

计时前预先计算同场景离线参考，避免首个策略承担参考冷启动。策略计时包含缓存后的评分审计，外层最终独立验解在计时之外。每个输入/策略只计时一次，依种子轮换执行顺序；这是同模板小样本探索，不能提供稳定吞吐率、显著性或未知仓库泛化结论。

## 4. 实测结果与原因

下表是每类6个种子的均值。`F改善` 为相对配对基线的分数下降百分比，正值表示改善、负值表示退化；时间和里程均按离散步计。

| 场景 | 策略 | F | F改善 | T | R | D | 运行秒 |
|---|---|---:|---:|---:|---:|---:|---:|
| 静态分层 | baseline | 1.00000 | 0 | 176.17 | 87.19 | 617.33 | 0.478 |
| 静态分层 | sipp_budget | 0.99922 | +0.078% | 176.00 | 87.14 | 617.00 | 0.913 |
| 静态分层 | sipp_matching | 1.00675 | −0.675% | 176.00 | 87.44 | 632.00 | 0.960 |
| 动态设备 | baseline | 1.00000 | 0 | 171.83 | 45.74 | 891.33 | 0.500 |
| 动态设备 | sipp_budget | 1.00660 | −0.660% | 173.00 | 45.85 | 903.00 | 1.129 |
| 动态设备 | sipp_matching | 1.00947 | −0.947% | 174.67 | 45.61 | 899.33 | 1.127 |
| 动态共享 D | baseline | 1.00000 | 0 | 220.83 | 57.53 | 1003.33 | 0.563 |
| 动态共享 D | sipp_budget | 0.99989 | +0.011% | 221.67 | 57.42 | 998.67 | 1.202 |
| 动态共享 D | sipp_matching | 0.99680 | +0.320% | 220.50 | 57.35 | 998.33 | 1.200 |

数据来自 [`summary.json`](../results/v4/summary.json)，逐次值见 [`runs.csv`](../results/v4/runs.csv)。归一化是先对每个固定场景计算，再取分数均值；不能用表中跨种子均值重新计算出完全相同的 F。

结果暴露出三个具体制衡点：

1. **局部改善与最终目标不同。** 当前联合修复按“已接任务剩余交付时间之和、回库结束时间、移动量”的词典序接受方案，并非按最终 F 接受。它可能缩短一些已接任务的剩余时间，却改变后续接单时机，增加整批结束时间或里程。动态设备下 `sipp_matching` 的 R 略降而 T、D 增大，是指标此消彼长的一个例子；本实验没有单独消融证明具体某条路线导致退化。
2. **平均响应与尾部等待不同。** 共享 D 场景中 `sipp_matching` 的 R 改善0.314%，P90 却退化3.571%；`sipp_budget` 的 P90 退化5.893%。降低平均值不足以证明最慢订单得到照顾，需要同时保留公平性与尾部指标。
3. **搜索次数与质量余量不同。** 当前两个 SIPP 修复配置约为基线两倍运行时间，综合改善却最多约0.32%，还有负结果。分层固定装货和独立面的资源门槛会限制可重排空间；是否确实是主要瓶颈，仍需阶段分解与同语义小实例参考验证。不能据此直接把更多搜索预算或更大模型作为改进。

当前建议用 `baseline` 作为 V4 低开销参照和演示起点，将两个 SIPP 配置保留为实验选项。CLI 默认算法未改变，运行 V4 比较时显式传入算法。旧规则的396行实验、66种固定场景和15条历史轨迹验证仍通过，但与 V4 的货架几何、服务时长及 D 站合同不同，不混合排名。

## 5. 调研报告启发的下一步

用户提供的 `AGV_Report_28pages_Attachment.pdf` 第10–11节强调先诊断、建立2–4车同语义参考、再按反例选择阶段化搜索、有限 ETA 或事件预算。这一顺序适合 V4；其中旧布局的路径残差、旧训练模型和 ETA 负结果可作为提问线索，不能直接当作 V4 已验证结论。PDF 仅作研究输入，没有随源码公开复制。

以下除“已实现”外均为**拟实施实验**，不属于本次已交付算法：

| 优先级 | 可行操作与解释 | 比较及退出条件 |
|---|---|---|
| 已实现 | 审核后接入分层/D 站规则，修复验解与序列化，增加最多8次交付延迟尝试 | 反例通过；保留重试上限和非完备性说明 |
| P0 | 在 V4 逐单拆分待派、空载移动、装货前交通等待、装货、载货移动、卸货前等待、卸货，另计回库和 CPU；记录门控拒绝与修复调用/接受原因 | 各阶段加和必须等于订单耗时，移动/等待/服务不重复计数；先判断固定服务还是交通占主导 |
| P1 | 建立2–4车、少量订单、相同层序与 D 站规则的小实例参考；分开固定派单的路线参考与允许重新派单的调度参考 | 区分超时和证明无解；给出现有策略可改善的差距，避免将不同业务合同当作上界 |
| P2a | 对齐在线局部目标：在同一可见状态和候选池中，用已知订单的 T/R/D 增量及显式尺度构造代价；保留独立验解和安全回退 | 同预算消融；不使用未来订单或离线参考分母选动作；同时报告 F、P90、失败和 CPU |
| P2b | 若 P1 出现跨段反例，扩展取货—交付—退出联合搜索或带业务阶段的 SIPP，保留后续可行性所需的到达状态 | 先解决最小反例，再比较收益；不得无条件将早到状态支配晚到状态；服务不中断、D 站不滞留 |
| P3 | 先经过层/面门控生成合法配对，再从静态近邻和最老订单中取候选；只给高压力配对计算少量 SIPP ETA，并独立消融预约提交顺序 | 相同输入、候选预算与公平回退；不可通过少接单获得较低均值，报告匹配数和尾部响应 |
| P4 | 按新单发布、服务完成、明显冲突压力触发重排；低压力时降低候选预算 | 计算成本应实际下降；事先约定允许的质量退化和失败阈值，而非只看候选数 |
| P5 | 在证据支持后扩展合法的任务接续/待命/调位状态，再研究学习排序 | 需先定义任务归属切换、冻结服务、停止和回库合同；不能通过伪造订单或读未来需求调位 |

最直接的下一轮建议是 P0＋P1，并单独试验 P2a。当前已经有明确的目标不一致问题，先验证目标对齐的边际收益比直接引入 RL/GNN 更容易解释。若参考显示交通余量很小，应转向交付点配置、层服务时间与流程设计；若出口耦合确实造成大量不可行，再投入 P2b。后续训练应等候选池、标签和目标固定后，使用 V4 独立场景/地图划分，而不是把同场景候选行随机拆分当作泛化证据。

## 6. 复现与证据边界

安装后从项目根目录运行；输出目录须尚不存在，单次输出默认拒绝覆盖：

```bash
python -m pip install -e '.[dev]'
python -m unittest discover -s tests -t . -v
ruff check src tests
ruff format --check src tests
agv run --profile v4 --mode dynamic --vehicles 10 --layers 3 \
  --obstacles columns_equipment --tasks 24 --algorithm baseline \
  --output runs/v4-baseline.json
agv run --input runs/v4-baseline.json --algorithm sipp_budget \
  --output runs/v4-sipp.json
agv benchmark-v4 --seeds 6 --output runs/v4-reproduction
python scripts/verify_v4.py
python scripts/verify_results.py
agv serve
```

`--input` 复用完整场景且重算策略，不信任文件内旧结果。网页新建场景有有限上限；导入限制为96×96、10车、60单、1800步，无截止文件用 CLI。完整测试数是本次本机测得状态，跨平台 CI 以对应提交的 Actions 结果为准。原始队友目录与 PDF 属于审核输入；公开仓库保留模块化实现、必要来源说明和精简可复核证据。

`verify_v4.py` 独立重建全部54行的指标关系、配对摘要和同场景参考，并验解6条保存的完整轨迹；它不重新计时全部策略。证据清单见 [`review-validation.json`](../results/v4/review-validation.json)。可导入网页的固定示例为 [`v4_small_dynamic.json`](../examples/scenarios/v4_small_dynamic.json)。本次也在源码目录外安装0.3.0 wheel，验证了10车 V4 SIPP 运行及打包页面资源。
