# 订单搜索与多车路径协调：方法及证据边界

本轮从固定的 `cd8d1be` 架构分支独立开展，不改变现有注册算法、默认入口、仓库布局、层序、服务时间、四邻接和独立验解器。完整实验统计由 `runs/search-holdout-final-20261021/summary.json` 生成，交付包在 `results/search-research-20261021/` 保存紧凑副本和原始轨迹归档。

## 推荐与实际实现

| 方法 | 本轮用途 | 与课程的对应 | 保证边界 |
|---|---|---|---|
| 排列遗传算法 GA | 搜索已出现订单的优先顺序；真实 SIPP 推演筛选 | 教材6.2：编码、适应度、选择、交叉、变异 | 多车在线情形为启发式，无近似比保证 |
| BFS、时空 A*、SIPP | 障碍感知距离、原基准和安全时间区间路线 | 教材5.3.2、5.4.3 | 单段最早完成不等于综合调度最优 |
| 预约优先级搜索 | 在不改变车—单对应关系时交换规划顺序，复算完整路线 | 教材11.4多智能体协调；启发式搜索 | 有限候选，不是完整CBS或MAPF-LNS |
| 精确动态规划 | 单车静态参照 | 状态空间与最优子结构 | 仅适用于说明中的严格子类 |
| 指派/顺序穷举＋下界达成证书 | 2车3单参照 | 搜索、约束与最优性验证 | 只有合法上界与严格下界相等才认证 |

进一步候选包括 ALNS、CBS/EECBS。它们不是本轮已经实现或验证的完整算法，也不能将论文保证直接继承到项目的加权目标。

选型建议如下，避免仅为覆盖教材而堆叠算法：

| 候选 | 适合本问题的部分 | 本轮决定 |
|---|---|---|
| GA＋SIPP | 离散订单顺序、车辆分配解码、真实可行路线评价 | 实现并作为主比较；交叉和变异确实改变订单排列，不是给原贪心改名 |
| ALNS＋SIPP | 从现有方案移除一组订单再重插，可进一步调整任务归属 | 下一阶段候选，本轮不宣称其收益 |
| 合同网/拍卖＋SIPP | 车辆按预计完成成本投标，适合解释在线多智能体协作 | 可作为课堂基线，当前没有实现完整拍卖协议 |
| ACO | 把订单衔接作为构造图，在多次构造中更新信息素 | 可作第二种教材对照；动态订单、层序和拥堵仍需专门解码 |
| 离散PSO | 搜索分配与顺序 | 需额外定义离散位置/更新算子，本轮优先采用排列GA |
| CBS/EECBS | 固定任务或航点后的多车碰撞协调 | 后续路径模块候选；先定义项目服务和资源约束如何进入高低层搜索 |

报告中可用“基准规则→教材GA→真实路线筛选→小规模精确认证”的逻辑说明课程知识怎样解决实际约束，再通过消融说明每层作用。GA只搜索订单优先级，车辆由解码器逐次选择；并没有穷举所有车—单映射，所以不得称其为完整联合全局优化器。小规模最优值用于量化差距，不参与GA输入。

遗传算法使用订单ID排列；16个个体、12代、锦标赛选择、顺序交叉、交换变异和精英保留。预约无关的静态排程只负责便宜筛选；排名靠前的最多3个排列通过真实执行内核和SIPP进行完整可见订单推演。未找到预测改善时保持贪心。新订单出现可重新搜索；只读取观察，不访问未发布订单、流关闭时刻或总单量。实际评价始终使用生产评分器固定的同场景参照。

在线适应度和推演筛选以当前可见工作的基准预测作局部归一化，三个系数仍为0.5、0.3、0.2。它们是搜索代理，不是离线全场景F的精确增量；动态运行时也不读取包含未来订单信息的评分分母。最终实验F由独立评分器计算，因此“预测改善”不能代替实际收益，更不能保证每一场景改善。

多车预约优先级搜索最多比较8种顺序；每个候选都重新规划完整取货、送货和安全返回路线，设置2000步、120次路线调用和30000次展开的预测预算。超预算或不完整的预测不能胜出。它不改变任务归属，不能中断装卸，实际提交仍经过现有命令网关。联合配置只是探索性消融，不能根据留出集逐场景挑选最佳策略冒充一个在线算法。

## 单车精确参照的证明

适用条件：V9.1、1辆车、1至14单、全部release=0、订单流在0时刻关闭、无仿真时域上限。仍使用原图、取货候选侧、独立货架排、层序、2l取货时间、卸货服务、专用D与最终返回H。

定义 `a=0.5/Tref, b=0.3/(n Rref), c=0.2/Dref`。目标是 `a T + b sum(Cj) + c D`。

每单结束于其固定D。对固定顺序，任何额外等待或绕行都不能改善三个正权重指标；因此每单的最短合法“前往取货+载货到D”行程支配更长行程。各取货候选侧须在同一次行程内联合比较，不能拼接不同侧的最短片段。

令M为完成任务集合，k为上一个D。下一单j的移动长度为d，服务时间加移动为Δ。Bellman递推的增量为：

`[a + b (n-|M|)] Δ + c d`。

原因是这段时间对最终T贡献一次，对尚未完成的每单完成时间各贡献一次。终态只增加 `c distance(last_D,H)`，因为最后返库距离计入D，但其耗时不计入T。对合法层序的所有下一单取最小即可；状态为 `(M,k)`。权重用有理数放大成整数，避免以浮点容差“制造最优”。测试另以全部排列穷举及真实轨迹验证。

`exact_single` 对不支持的模型明确报错。实验runner的 `mode='exact'` 是研究组合入口：仅满足上述条件才输出精确证书，其他场景可能走GA分支；不能仅凭mode字段声称多车最优，应检查 `decisions[].method` 与证书scope。

## 多车小规模证书

对2车3单静态场景枚举 `2^3 × 3! = 48` 个指派/顺序组合。每条车链保留自己的H、任务D、合法取货候选和服务时间，优化同一加权目标；只放松车间碰撞与跨车资源时序。真实可行解都映射到这个放松集合，所以其最优目标是严格下界。

再将所选车链交由真实SIPP执行，并通过原独立验解器。仅当真实执行的加权目标与下界以精确分数完全相等，才签发原问题的最优证书；不相等则保留未解决差距。四档图、种子62/63的8例均达到下界，原始场景、实际轨迹和上下界分数一并保存。这不是全部多车实例的完备求解器，也不保证任意实例都能认证。

另一次40例探测发现，已有的T/R/D分项松弛下界都未被同时达到。此负面结果说明松弛可能太宽，不能据此判定当前解一定不优或直接算出“还可下降多少”。

## 实验协议与复现

开发：6个固定场景，种子60/61。控制器基线均值比1.0，预设目标≤0.98；一次保留的GA源码试验达到0.939287，即平均下降6.0713%。这里不是留出结果。

最终留出：固定算法源码和参数后，四地图×三类工况×六个新种子3000至3005，共72个场景。主比较为GA对贪心；路径协调只在预设的8个多车静态场景消融，BCRD尾部保护与ETA定位延迟在预设的24个中/大型多车场景比较。总计208次执行。各工况都设8层上限；单排仍只有一层。失败保留，先独立验解再评分。按种子聚类bootstrap，避免把同种子不同模板当成完全独立的样本。

前一轮使用1000至1005种子，在完成178次执行后因超大图推演耗时过长而中断，没有形成完整留出结论。已完成记录和原源码指纹保存在 `interrupted-phase/`，未按收益删除样本。随后增加了空决策事件跳转，并为探索性的预约优先级预测设置上述预算；在查看最终新种子结果前重新冻结源码和协议。

事件跳转只适用于原默认推演，以及明确声明“空决策无状态变化”的订单优先级驱动器；任意自定义回调仍默认逐步调用。所有物理时间步仍交给原内核推进并记录，只跳过无法派单时重复生成观察的工作。专项差分测试要求完整预测结果（扣除计时字段）与逐步版本相等，开发6例最终指标亦与优化前逐项一致。这是推演性能修正，不是改变车辆运动或业务时间。

源代码在整轮评估期间保持指纹一致；计时使用轮转策略顺序，但存在并发计算，CPU比只作为描述性开销，不是隔离硬件性能结论。所有数据均为既定合成布局，不是实际电池测量或未知仓库泛化试验。F下降不意味着T、响应、里程、P90每项都改善。最终返库和重定位移动完整计入D，能耗仍是0.05D。

## 冻结结果与采用决定

最终208次执行全部有效。GA对同一SIPP内核的贪心派单，在72个新场景中72胜，平均F下降7.7496%，六种子聚类bootstrap的95%区间为[6.9565%, 8.6376%]。单车静态、四车静态、四车动态分别下降5.6082%、8.8981%、8.7426%。这是各场景相对改善比例的算术平均，不是把所有场景的总成本相加再求比例。

GA平均CPU耗时比为4.5273；不是实时性保证。P90在72例中的2例变差。与ETA定位延迟策略的24例直接比较中，GA有21胜3负，不能称它支配所有备选方法。BCRD尾部保护在所比较的24例中与贪心相同，不代表它在所有积压分布中无效。

预约优先级调整单独对贪心仅8例中的1例微幅改善；叠加到GA后8例全部持平，平均耗时变为GA的2.7063倍。因此采用决定为显式推荐“GA订单顺序搜索＋原SIPP”，不推荐默认叠加本轮有限预约顺序搜索。没有把未显示收益的部分包装成成功的路径改进。后续若做CBS/EECBS或MAPF-LNS，应另立协议，并在更高拥堵及服务资源冲突场景中检验。
