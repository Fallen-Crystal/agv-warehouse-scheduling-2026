# V9.1 仓库建模规范与算法接入合同

## 1. 版本约定与快速运行

V9.1 明确定义了在线订单流下的核心执行规则：**批次之间原地或安全选点待命，所有批次完成且订单流显式关闭后全车最终返库**。本版本使用独立 profile `v9.1`，与旧版 `v9`、`v4`、`legacy` 及其历史实验归档完全隔离。

```bash
python -m agv run --profile v9.1 --mode dynamic --tasks 12 --vehicles 4 --output runs/current.json
python -m agv serve
```

CLI 默认采用 `sipp_stream_dispatch`（SIPP + 同规则距离贪心），也可用 `baseline`（时空 A* + 距离贪心）作为离线参照；Web 端默认选择 V9.1 并按“全部订单完成且全车返库”自然终止。从 `0.6.0` 起，V9.1 额外提供显式可选优化算法入口：`sipp_stream_matching`、`sipp_position_dispatch`、`sipp_position_matching_dispatch`、`sipp_position_delay_dispatch`、`sipp_stream_bcrd` 与 `sipp_stream_bcrd_tail`，其实现细节与留出实验结果见 [V9.1 调度与待命优化报告](v91-optimization.md)。针对旧版规则设计的历史算法入口在 V9.1 下会明确报错拦截，保证实验口径一致。

## 2. 仓库几何与货位规则

V9.1 提供四档标准地图（默认作业通道宽 2 格）：中型 `46×41`、大型 `62×47`、特大 `78×65`、超大 `96×69`。支持最多 10 辆同构 AGV，每车在左侧拥有专属停车位 `H`。车辆按离散时间步执行四邻接移动或原地等待（单步 1 格），严格禁止斜走、穿障、同格顶点碰撞与对向边交换。

布局与货位约束如下：
- **货架分区与单双排**：中央设备位于上下两个水平货架区之间；水平列中线固定，短长架居中对齐，各区前 50% 行短、后 50% 行长。首排为仅含 `L01` 的单排货架，允许从两侧合法停靠格取同一货位并共享同一资源锁；其余水平及右侧竖架均为背靠背独立双排，各自独立编号、库存独立且只能从各自外侧取货。
- **层数与装卸时长**：双排支持 3–8 层（`L1` 为最底层，层号越大越高），取货装货耗时 `s_l = 2l` 步，卸货固定 1 步。每张订单固定指定独立排 `R`、货格 `B`、层号 `L` 与出库口 `D`，算法保持订单属性不变。
- **净空与障碍**：横竖取货区之间留有至少 3 个纯空白格，左右外侧等宽；墙边上下净空按四档尺寸分别为 `2 / 3 / 3 / 4` 格，设备与上下取货区净空分别为 `1 / 2 / 3 / 4` 格（均不含作业区）；立柱总数依次为 `4 / 6 / 8 / 12`。设施、外墙与货架实体不可通行，入库口 `I` 仅作布局标识。
- **作业区与 D 站权限**：作业地面允许他车通行，装卸占用的当前格不可穿越；`D` 站仅在对应订单卸货区间内由本订单车辆占用，禁止穿行、提前排队或卸货后滞留。

## 3. 层序锁、待命机制与订单流关闭事件

- **任务绑定与层序优先**：每辆车从派单成功至卸货结束只绑定一张订单；每个独立货架格从派单至装货完成期间锁定，后续同格订单留在待派池中。资源空闲时，从当前已发布未派订单中按 `(-层号, release, id)` 严格执行高层优先；尚未发布的未来高层订单不影响当前低层派单，也不会抢占已承诺任务。
- **默认原地安全待命**：在默认策略下，车辆卸货后立即离开 `D` 站并在普通通行地面（排除取货作业格、`D` 站与他车 `H`）原地安全待命，不设固定待命时长上限，也不随机游走。新订单直接从当前位置接续；若阻碍同伴已承诺路线，则沿安全兜底返程让行。位于 `H` 中尚未出动的车辆保持原地待命。
- **可选主动选点调位（0.6.0+）**：显式启用定位策略后，系统可依据已观察历史需求主动调动空闲车辆（含 `H` 中车辆）前往安全普通地面或返回自身 `H`；重定位行程计入实际空驶与总里程 `D`，并全程保留可中断的安全返 `H` 兜底路径。`env.reposition(vehicle, target)` 仅作空闲调位，不触碰已绑定任务或装卸，且在车辆已位于自身 `H` 时拒绝重复请求自身 `H`。
- **外部订单流关闭事件**：正式场景包含整数 `order_stream_end = e`（不早于任何订单的发布时刻）。有限回放默认在最后一批订单发布时发出关闭信号，延后 `e` 可模拟批次间空档。`e` 属于外部发布器参数，在到达 `e` 之前在线算法通过 `observe()` 仅看到 `order_stream_closed = False, stream_closed_at = None`；到达 `e` 时才公开关闭状态与关闭时刻。
- **最终返库与终止条件**：`Environment(scene, stream_open=True)` 将流关闭控制权交给外部发布器（调用 `close_order_stream()`），未发布完订单前禁止关闭。只有同时满足“关闭信号已到达”且“所有已发布订单全部卸货完成”时，车队才启动最终返库；当全部车辆回到各自专属 `H` 后仿真正式终止，最终返库步数完整计入空驶、总里程 `D` 与估算能耗。

## 4. 数学模型与评价指标

设可通行网格图为 `G = (V, A)`，车辆 `k` 在时刻 `t` 的位置为 `p_k(t)`，满足单步移动或等待约束 `||p_k(t+1) - p_k(t)||_1 <= 1`，且任意两车无顶点碰撞与对向边交换。每张订单 `j` 具有发布时刻 `r_j`、货位 `b_j`、层号 `l_j`、出库口 `d_j` 与合法停靠格集合 `Q_j`。调度决策确定执行车辆 `k_j`、派单时刻 `a_j`、停靠格 `q_j ∈ Q_j`、装货起止 `[P_j, U_j]`、卸货起止 `[Qtime_j, C_j]` 及全车队轨迹，满足：

```text
r_j <= a_j <= P_j
U_j = P_j + 2 * l_j
Qtime_j >= U_j
C_j = Qtime_j + 1
```

装卸服务区间连续占位且不可中断，完成装货后方可载货前往 `D`。单车任务区间 `[a_j, C_j)` 互不重叠；同货位派单锁 `[a_j, U_j)` 互不重叠且满足已发布高层优先（单排双侧共享锁，背靠背双排独立）。

令外部关闭指示为 `z(t) = 1[t >= e]`，最终终止时刻 `B` 为同时满足 `z(t) = 1`、全部已发布订单卸货完成且所有车辆首次归 `H` 的时刻（`B >= e`；若为空订单流，订单指标记为 0，仍需等待流关闭）。

主综合评分保持固定权重与同场景离线基准归一化（越低越好）：

```text
T = max_j C_j
R = mean_j (C_j - r_j)
D = sum_{k,t} 1[p_k(t+1) != p_k(t)]    # 包含最终返库与重定位
E = 0.05 * D                           # 移动能耗代理
min F = 0.5 * T/Tref + 0.3 * R/Rref + 0.2 * D/Dref
```

其中 `E` 与 `D` 严格成比例，仅作展示而不重复加权；参考分母 `(Tref, Rref, Dref)` 固定取同 V9.1 场景下“距离贪心 + 时空 A*”的离线执行结果。系统同步汇报 `B`、平均派单等待、空载/载货里程、待命步数、交通等待、P90 订单耗时、工作量均衡度与 CPU 耗时；失败实例保留原始记录而不计入有效综合分数。以上数学模型精确刻画了轨迹与离散约束语义，为后续优化与下界推导提供统一依据。

## 5. 模块分工与独立验解合同

| 模块文件 | 核心职责 |
|---|---|
| `domain.py`, `warehouse/mixed.py` | 场景定义、规范几何校验与 `generate_current` 生成器 |
| `dispatch/order_stream.py` | 外部订单发布/关闭事件流与结束就绪判定 |
| `simulation.py` | 唯一真实执行状态、观测隔离、派单、推进与原子路线提交 |
| `dispatch/idle.py` | 普通地面安全待命与已承诺路线让行 |
| `dispatch/registry.py` | V9.1 与历史版本算法入口隔离注册 |
| `planning/` | SIPP/A* 单段搜索、预约表、取送组合与重定位路径规划 |
| `evaluation/validation.py` | 独立核验轨迹、层序、关闭事件、返库与统计指标 |
| `evaluation/objective.py` | 固定同场景离线参照计算与综合分数 `F` 评定 |
| `io/scenes.py`, `web/` | V9.1 场景持久化、校验导入与交互式动态回放 |

**关键执行与验解约定**（完整架构说明见 [系统架构](architecture.md)，操作指南见 [使用说明](usage.md)）：
1. **严格在线观测**：策略仅消费 `observe()` 返回的只读副本，动作以有序 `(vehicle, task[, pickup_point])` 批次提交；非法批次整体拒绝，合法批次内路径失败逐对反馈。
2. **推进与区间状态一致性**：`advance(n)` 最多推进 `n` 步并在仿真结束时提前返回；结束后再次调用不再推进时刻。`interval_states` 由真实执行事实生成并接受逐区间核验；已完成返库后若启动新定位行程，保留历史返库记录而不回写过去空闲时段。
3. **派单与最终返库核验**：派单记录按 `assigned_at` 单调递增，同刻按提交顺序保存；最终有效返库事件必须落在已执行轨迹内且对应实际 `H` 占位，终止时刻 `B` 为满足结束条件后首次全车归 `H` 的时刻，禁止追加冗余停车。
4. **零订单与安全输入边界**：零订单场景下若产生移动则标记为无有效归一化 `F`；场景目录拒绝未知字段与错误类型，畸形重规划请求抛出 `ValueError` 且保持环境原状态不变。

V9.1 阶段的完整验证证据与优化对比请见 [V9.1 优化报告](v91-optimization.md) 与 [独立审计清单](../results/v91/verification.json)。
