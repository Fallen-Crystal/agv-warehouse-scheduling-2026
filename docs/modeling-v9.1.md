# 当前建模与算法交接：V9.1

## 当前约定与旧实验边界

当前要求为：**批次之间待命，所有批次完成后最终返库。** 本版本使用显式 `v9.1` profile；旧 `v9`、V4、legacy 和其 SIPP/BCRD/有限待命实验均保留，不把旧实验改名成新规则结果。

```bash
python -m agv run --profile v9.1 --mode dynamic --tasks 12 --vehicles 4 --output runs/current.json
python -m agv serve
```

当前 CLI 不指定算法时使用 `sipp_stream_dispatch`；网页默认选择V9.1，隐藏旧模式的时间上限控件，按全部订单完成并返库结束。也可用 `baseline` 作为同规则距离贪心参照。输入文件以文件内 profile 为准，不能由生成参数偷偷改写。

`sipp_stream_dispatch` 复用原SIPP和距离贪心，不声称是新优化算法。历史 `bcrd_budget`、8/16/32步待命及联合修复未完成V9.1预测/重规划适配，不能直接混入当前profile；此类组合明确报错。算法同学可随后扩展，但须保持下面的观测和验解合同。旧论文实验收益仍只针对旧规则。

## 仓库与货位

四档地图默认作业宽2格：中46×41、大62×47、特大78×65、超大96×69；最多10辆同构车，各有独立左侧停车位H。四邻接移动或原地等待；一格一时间步，禁止斜走、穿障碍、同格碰撞和反向交换。

设备在上下两个水平货架区之间；水平列中线固定，短长架居中，各区前50%行短、后50%行长；首排是只有L01的一排货架，可从两侧取同一货位，资源锁共享。其余水平及右侧竖架为背靠背独立排，分别编号，货物不同，只能从各自外侧取货，不允许绕到另一排代取。

双排可设3—8层，L1为最下层，层号越大越高。取货时间 `s_l=2l` 步，卸货1步。每单指定独立排R、格B、层L及出库口D；这些均不能由算法换货或换交付点。

横竖取货区之间至少3个纯空白格，左右外侧等宽。墙边上下净空分别2/3/3/4格；设备与上下取货区净空1/2/3/4格；均不含作业区。立柱总数4/6/8/12，与上次审定几何相同。设施、边界及货架实体不可进，入库口I仅示例、不开放。

作业地面允许其他车辆通行，装卸占用格不可穿越。D只能在其指定订单卸货区间占用，禁止过路、提前排队、卸完停在D上。

## 层序、待命与结束事件

每车从成功派单至卸货结束只绑定一单。每个独立货架格从派单至装货完成锁住，下一单留在池中，不提前绑车等候。资源空闲时，在已出现未派订单中按 `(-层号, release, id)` 决定同格顺序。未知未来高层不阻塞当前低层，也不抢占已派订单。对面独立排互不共享锁；单排两侧属于同一货位、共享锁。

卸货后先离D，在普通通行地面原地安全待命，排除取货作业格、D和他车H。不设固定候车位、不设等待8步等额度、不主动随机游走。新单从当前位置接续；必要时沿已有安全兜底返程让开已承诺路线。H中的未出动车不自动重定位。待命不额外增加里程，但占用时间与地面资源。

正式场景必须带整数 `order_stream_end=e`，e不得早于任何订单释放。生成器的有限回放默认在最后批次发布时发出结束事件；显式延后e可模拟批次间空档。e只属于发布器输入，不传给在线算法；算法在事件前只能看到 `order_stream_closed=False, stream_closed_at=None`。到e时公开关闭信号及已发生时刻。

`Environment(scene, stream_open=True)` 将关闭交给外部发布方，在声明时刻调用 `close_order_stream()`；它不是策略动作，不能在仍有未发布订单时关闭。该接口控制已声明有限流的关闭，不代表实现了运行中任意追加订单的网络协议。

关闭信号到达，且所有已发布订单已完成卸货后，才恢复最终返库；全部车实际回到自身H才终止。暂时pending为空不能终止或推断未来没有订单。最终返库计入空驶、总里程和估算能耗。

## 数学模型及指标

图G=(V,A)由可通行网格及四邻接边构成；每辆车k的位置为p_k(t)，移动或等待满足 `||p_k(t+1)-p_k(t)||_1<=1`。不同车不得同格、不得在同一时间区间沿同边相向交换。H为车辆专属，D受服务窗口限制。

每单j具有释放r_j、指定货位b_j/层l_j/出口d_j、合法装货格集合Q_j。决策包含所属车k_j、派单时刻a_j、停靠q_j∈Q_j、取货开始P_j/结束U_j、卸货开始Qtime_j/结束C_j及全车队路径。满足：

```
r_j <= a_j <= P_j
U_j = P_j + 2*l_j
Qtime_j >= U_j
C_j = Qtime_j + 1
```

服务区间连续占位、不可中断；取货完毕后才可载货去D。车辆任务区间 `[a_j,C_j)` 不重叠；同货位派单锁 `[a_j,U_j)` 不重叠并满足已发布订单高层优先。单排双侧共享这一资源，背靠背两排独立。

结束信号 `z(t)=1[t>=e]` 由发布器给出。最终返库准备条件是z(t)=1且已发布订单全部卸货；B为实际全车队归H并满足结束条件的时刻，B>=e。空订单而e延后也必须等待关闭；订单指标按零任务约定为0。

主目标保持固定权重、同场景离线基准归一化：

```
T = max_j C_j
R = mean_j(C_j-r_j)
D = sum_{k,t} 1[p_k(t+1) != p_k(t)]   # 含最终返库
E = 0.05*D                             # 能耗代理，不是实测kWh
min F = 0.5*T/Tref + 0.3*R/Rref + 0.2*D/Dref
```

E和D严格成比例，不重复作为两个独立目标加权；归一化能耗与归一化里程相同。参照使用相同V9.1场景、结束信号、层序和待命规则的固定距离贪心+A*，不使用候选自身分母。基线F通常为1，不表示最优。不可直接横比不同地图、规则或不同基准的F。

辅助报告B、平均派单等待、空载/载货里程、待命步数、交通等待、P90订单耗时、工作量差异与运行CPU。失败保留但无有效综合分数，不与成功实例混算成绩。没有新增紧急程度、截止期、充电、电池容量或异构车辆。

这是轨迹及逻辑约束建模，尚不是可直接求解的MILP程序。SIPP单段最早到达、局部派单或一次参考运行都不等于全局最优；本次没有新增算法优劣实验。

## 算法接入与验解

|文件|职责|
|---|---|
|`domain.py`, `warehouse/mixed.py`|场景、规范几何与 `generate_current`|
|`dispatch/order_stream.py`|外部发布/关闭事件，结束就绪条件|
|`simulation.py`|真实状态、观测、派单、推进、原子路线提交|
|`dispatch/idle.py`|普通地面安全待命与已承诺路线避让|
|`dispatch/registry.py`|当前与历史算法入口隔离|
|`planning/`|保留SIPP/A*和预约路径规划|
|`evaluation/validation.py`|独立轨迹、层序、事件与统计核验|
|`evaluation/objective.py`|固定同场景参照及F|
|`io/scenes.py`, `web/`|保留V9.1格式的保存、导入与动态回放|

策略只接收 `observe()`，不得读取环境完整场景或未来订单。动作仍为有序 `(vehicle,task[,pickup_point])` 批次；非法输入整批拒绝，合法输入的路径失败逐对反馈。当前在线接口不等于任意全场离线轨迹优化器。

最终有效返库事件必须落在已执行轨迹内并对应实际H占位，不能填写卸货时刻充当返库或把返库写在成功轨迹之后；被下一单打断的旧兜底返程仍可保留。关闭状态/时刻、层序、D权限及指标也独立核验。正式目录拒绝未知/额外字段与错误类型，防止未来信息混入公开地图；畸形重规划以ValueError拒绝且不改环境。

后续新增算法应先在这一合同上完成，再做同场景配对。不要将旧BCRD分数或有限待命统计直接作为当前模型效果。验证命令与本次实跑结果见 [V9.1验证](v9.1-validation.md)。
