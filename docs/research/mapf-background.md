# 仓库 AGV 在线联合重规划：MAPF/MAPD 文献调研与算法设计

调研日期：2026-10-14

本文梳理了多智能体路径规划（MAPF）与在线取送货（MAPD）领域的核心文献，阐述本项目将滚动时域协调与大邻域可行解修复思想融入仓库 AGV 调度的算法设计与边界定义。所有文献引用均核对至正式出版方或作者原文，项目实测数据见各阶段实验报告。

## 1. 问题定位：在线多智能体取送任务（MAPD）

本仓库场景属于典型的在线多智能体取送任务（Multi-Agent Pickup and Delivery, MAPD）：订单随时间陆续发布，AGV 需依次驶向货架合法取货侧、完成连续装货、驶向出库口完成卸货，并最终返回专属停车位；车队共享路网，须严格避免同格顶点冲突与对向边交换冲突。

在原版代码中，`Environment.assign()` 于接单瞬间调用 `plan_task()` 一次性预约“取货 → 交付 → 返程”整条路径，`Router.leg()` 通过时空 A* 规避既有预约，之后 `advance()` 严格按既定计划逐步执行。该机制虽然安全，却缺乏在执行途中联合修订多辆忙车未来路线的接口——先接单车辆长期占据关键通道，后接单车辆只能单方面绕行或等待，即使互换通行次序能使车队整体更快也无法协商。

经典 MAPD 理论由 [Ma 等（AAMAS 2017）](https://jiaoyangli.me/files/2017-AAMAS.pdf)（另见 [CMU RI 记录](https://publications.ri.cmu.edu/lifelong-multi-agent-path-finding-for-online-pickup-and-delivery-tasks)）系统定义，其在满足特定拓扑条件的 well-formed 实例上给出了 TP/TPTS 的完备性理论；对于本项目的一般教学仓库布局，需要面向实际障碍与业务规则设计兼顾安全性与效率的在线协调机制。

## 3. 融合方案设计：在线联合后缀重规划

基于上述对比，本项目选择 **受 RHCR 与 MAPF-LNS 思想启发的在线联合后缀重规划**，低层沿用优先级规划与时空 A*（后续在 v2 中扩展支持 SIPP）。与原论文相比，本工程适配保留了两项贴合业务合同的关键特征：一是重规划默认在每 5 步或新订单指派后触发，且始终校验直至回库的完整剩余路线，确保环境任何时刻都持有完整可执行兜底计划；二是邻域采用轻量级全车队优先序轮换与相邻车对（而非完整自适应邻域库），在课程算力预算内快速产出可解释改进解。

### 3.1 冻结历史事实，仅优化可修改未来

在仿真时刻 `t`，车辆已执行的轨迹前缀与已接订单归属均不可回写，确保所有收益均来自真实的路线与通行次序优化。各执行阶段的状态保留规则如下：

| 当前状态 | 冻结的不可逆事实 | 可重规划的未来后缀 |
|---|---|---|
| 去取货 | 已分配订单、当前车位 | 未来取货路线、尚未开始的停靠侧选择、送货及回程 |
| 正在装货 | 当前停靠格、原装货开始时刻、已服务步数 | 冻结剩余连续装货占位，优化服务结束后的送货与回程 |
| 去送货 | 已完成取货的事实与历史服务记录 | 未来送货与回程路线 |
| 正在卸货 | 当前送货格、已执行卸货步数 | 冻结剩余卸货占位，优化卸货结束后的回程 |
| 正在返回 | 已完成送货记录 | 剩余回程路线 |
| 停车空闲 | 当前专属停车位 | 无新任务时原地保持 |

`repair_vehicle()` 在构造新路线时将未完成的装卸服务冻结为原地等待段；若先规划车辆的候选路线侵占了后规划车辆的冻结服务格，该候选直接放弃，确保绝不中断正在进行的装卸作业。

### 3.2 联合修复与原子提交机制

针对选中的车辆集合，系统临时释放其可修改未来后缀的预约，保留固定车辆预约及全部冻结服务段，随后按多个候选优先级顺序逐车重新搜索时空路径（将每车新路径依次写入候选预约表）。这里的“联合”体现为多车未来路线在候选层面协同变化并作为整体原子验收：若完整候选无法修复或未带来严格改善，则整体保持原方案，杜绝“部分车辆换路成功、部分失败”的不一致状态。

在 v1 实现中，`JointPlanner` 对有剩余路线的车辆生成轮转顺序、反序及基于当前时刻种子的随机排列（默认最多 8 个全车队候选），再补充车辆 ID 相邻的局部车对修复。

### 3.3 字典序目标函数与独立审计

同一时刻面对同一批已接任务，算法按以下字典序最小化三元目标：

```text
(sum(max(0, delivery_end - now)),
 max(now + len(vehicle_suffix) - 1),
 sum(remaining_move_actions))
```

三项依次衡量：当前未交付任务的预计剩余送达总耗时（已完成任务贡献为 0）、全车队最晚返库时刻、剩余移动步数之和。仅当候选路径完整可行且三元目标严格下降时，`Environment.apply_replan()` 才在独立审计副本中运行全量剩余轨迹、调用 `validate()` 复核历史与未来的一致性、重算真实前后目标并写入 `replanning_events` 后完成原子提交。

### 3.4 可选的可见订单批次匹配

独立于路径协商，`matching_action()` 基于车辆位掩码动态规划（最多 8 辆车）对当前已发布待派订单与空闲/返程车辆求解“最大匹配数前提下的静态最小代价”：

```text
min_over_pickup_candidates(distance(current_position, pickup)
                         + distance(pickup, delivery))
+ pickup_service + delivery_service - 0.25 * visible_order_age
```

其中年龄权重 `0.25` 鼓励优先照顾等待较久的订单。该匹配对当前静态代价矩阵求精确解，但在多车动态拥堵环境下与时空预约的交互需要通过消融实验检验（四组对照：原基线、仅匹配、仅联合重规划、匹配 + 联合重规划）。

## 4. 可解释性验证与算法边界

本方案的核心机理在于打破“先接单者永久锁定窄道”的静态约束：当窄门或交叉口发生竞争时，允许两辆或多辆忙车同步调整未来路线，让急迫或短链路车辆先行，另一辆车以小幅让行或绕行换取车队整体预计送达耗时下降（例如原计划 A 先过门、B 等 8 步，改排后 B 先过门、A 仅等 2 步，净省 6 步）。在轨迹分析中，需同步展示改路时刻、前后预计完工时间、窄门通过顺序、交通等待变化以及完整的配对成功率与计算耗时。

从理论性质上看，在线联合后缀重规划属于**有限预算下的启发式可行解优化**：
- 有限的优先顺序集合、逐段拼接的“取货 → 交付 → 回程”路径（原 RHCR 论文第 4.1 节指出需用多标签状态处理多目标间的时间依赖）、在线信息隔离以及保持既有订单归属，共同决定了该算法侧重在实用计算预算内搜索更优可行解，而非追求全局离线最优或完备性。
- 论文原创算法（CA*/WHCA*、RHCR、MAPF-LNS、MAPF-LNS2、CBS）归属原作者；本项目的核心工程与研究贡献在于将滚动联合后缀修复严谨地嵌入多阶段装卸执行环境，构建起状态冻结、原子审计、事件可解释回放与系统配对消融验证闭环。
