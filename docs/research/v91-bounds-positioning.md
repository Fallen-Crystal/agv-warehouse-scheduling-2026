# V9.1：可证下界、待命选点和因果边界

日期：2026-10-17。本文记录文献依据与本项目的数学推导；测得的改进幅度应另见同版本配对实验，不能用下界代替实际实验。

## 文献能支持什么

Ma、Li、Kumar、Koenig 的 *Lifelong Multi-Agent Path Finding for Online Pickup and Delivery Tasks* 在 §3.2 Definition 1 中定义 well-formed MAPD：任务有限、非任务端点不少于车辆数，且任意端点之间存在不穿过其他端点的路径。其 Token Passing 在空闲位置阻挡待执行任务的卸货点时才转移，否则允许原地休息。这支持“停车应避开业务端点与必经通道”的设计方向；仅排除割点和低度节点，尚不等于满足该论文的全部条件，也不能据此声称本项目新策略完备。[作者版论文，AAMAS 2017，§3.2、§4.1](https://jiaoyangli.me/files/2017-AAMAS.pdf)

Treleaven、Pavone、Frazzoli 的 *Asymptotically Optimal Algorithms for Pickup and Delivery Problems with Application to Large-Scale Transportation Systems* 将 stacker-crane 巡回分为载货段和卸货到下一次取货的连接段；Theorem 5.4 的证明指出，连接段形成某个二分匹配，其费用不低于最优匹配费用。Remark 5.5 讨论多车巡回。这里借用的是“将真实路线映射到更宽松的匹配问题”的证明思路，不移植其欧氏随机模型或渐近近似保证。[作者实验室版论文，Theorem 5.4、Remark 5.5，PDF 第18页；所链接版本标为2012年预印本](https://stanfordasl.github.io/wp-content/papercite-data/pdf/Treleaven.Pavone.ea.TAC13.pdf)

Frieze 与 Sorkin 在作者版论文开头区分一般置换指派与单一环巡回，并给出指派最优值不大于巡回最优值。放松环的连通性会得到若干独立子环，因此“指派松弛”是下界，不能称为已经找到可执行的精确任务路径覆盖。[作者版论文，§1，PDF第1—2页](https://www.math.cmu.edu/~af1p/Texfiles/atsp.pdf)

## 先修正建议中的两个公式

`release + distance(initial_home, pickup) + loading + loaded + unloading` 一般**不是**完成时间下界。车辆可能在订单发布前已经靠近取货点，也可能由上一单卸货点直接出发。把发布时刻与整段初始行驶时间相加，会把可以重叠的时间重复计算。

一个极小反例：初始到取货点2步，订单在50发布，取货1步、载货5步、卸货1步。允许离线预定位的车辆可以在2时刻到取货点，等到50后服务，在57完成。`50+2+1+5+1=59` 超过该可行完成时刻。下界必须使用 `max(50,2)+1+5+1=57`。离线下界允许车辆“预知”位置，是为了放松问题；在线算法仍不能读取未来订单。

`sum(loaded_distances) + n×n(delivery→pickup) assignment` 对有初始车辆起点的有限任务链也不一定有效。例如仅一个任务时，实际第一段是 Home→pickup，并不存在上一单 delivery→pickup。若把“最后一单回第一单”的边强制算进去，可能多算距离。必须把每辆车的初始、最终 Home 放进放松问题，或显式使用零费用虚拟终点得到更松的开放链下界。

## 实现接口与静态距离

实现位于 `agv.evaluation.bounds.lower_bounds(scenario)`，返回 `T`、`R`、`D` 与分项 `details`。输入先执行 `scenario.check()`；不写回场景；没有额外依赖。此接口只用于完整场景的**离线报告**。它不进入 `observe()`、在线派单或在线需求热度，也不替换既有评分分母。

记 `d_v(a,b)` 为车辆 `v` 的静态最短距离。通过项目现有 `Router` 的反向 BFS 计算，保留障碍物、禁止其他车辆 Home、卸货口只能作为相应交付目的地的约束。冲突、预约、资源竞争、层序先后被忽略，因此距离不会高于相同起终点的实际合法行驶长度。

单独的“从初始 Home 到第 j 单取货点”的时间界有额外细节：此前可能已经合法服务并离开过其他卸货口。因此该初始时间距离 `d^0_v` 进一步允许途经卸货口格子，仍保留障碍和他车 Home 禁行。第一单和相邻两单的连接距离继续使用严格的 `d_v`。生成地图的边界卸货口通常不形成这种捷径；实现仍在证明层面保留该放松。

每单可行选项是 `(vehicle, pickup_side)`。装货后到卸货的距离必须与同一个车辆、同一个取货侧计算。对不同边分别取最小值会破坏全局一致性，但这种一致性放松只会降低下界；实现不会把左侧的最短接近与右侧的最短载货错误拼成同一条入边。

## T 与 R 的证明

对订单 `j`，令发布时刻为 `r_j`，服务总长为 `s_j = pickup_service + delivery_service`，合法取货侧集合为 `Q_j`。定义

```text
c_j = min_(v,q∈Q_j) [max(r_j, d^0_v(H_v,q)) + s_j + d_v(q,D_j)]
T_individual = max_j c_j
R_LB = mean_j(c_j - r_j)
```

在任何完整实际解中，执行该订单的车辆从自身初始 Home 出发，到其实际取货侧至少需要 `d^0_v` 步；开始取货不早于 `r_j`；之后必须完成服务和载货路段。所以实际完成时刻不小于所选车辆与侧对应的表达式，更不小于对所有选项取最小后的 `c_j`。逐单取最大与求平均分别保留下界关系。

另外计算一个不计最终返库的移动下界 `D_prefix`：以所有初始 Home 和所有任务 delivery 为前驱，给每个任务分配不同前驱，任务不能以自身为前驱；入边包含到取货侧的空驶与该任务载货。真实任务链提供合法的一对一前驱关系，所以此矩形最小费用指派不高于最后一单完成前的实际总移动量。再加全部服务时间，最多 `m` 辆车并行：

```text
T_workload = ceil((D_prefix + sum_j s_j) / m)
T_LB = max(T_individual, T_workload)
```

最终返库可能晚于最后交付，不能把包含最终返库的 `D_LB` 直接代入这个工作量界。`T` 也不是等待订单流关闭的时刻。

## D 的闭合指派证明

本项目完整解要求车辆最终返回自己的 Home，`moves` 包含重定位与最终返库。构造 `(n+m)×(n+m)` 方阵，左侧节点是 `m` 个初始 Home 与 `n` 个任务 delivery，右侧节点是 `n` 个任务与 `m` 个结束 Home。

| 入边 | 费用 |
|---|---|
| 初始 Home_v → 任务 j | 对该车合法取货侧取 `min_q[d_v(H_v,q)+d_v(q,D_j)]` |
| 任务 i → 任务 j，i≠j | 对车辆和合法取货侧取 `min_(v,q)[d_v(D_i,q)+d_v(q,D_j)]` |
| 任务 i → 结束 Home_v | `d_v(D_i,H_v)` |
| 初始 Home_v → 自身结束 Home_v | 0，表示该车不接任务 |
| 任务 → 自身；初始 Home_v → 其他 Home | 禁止 |

实际解中，每辆车的顺序是 `H_v → j1 → j2 → … → jk → H_v`；把每条边映射到上述方阵，正好形成完美指派。每条入边的静态费用不高于实际对应移动段，车辆在两单间绕行或重定位只会增加实际长度。空闲车辆使用自身 Home 的零边。因此最小费用完美指派 `D_LB` 不大于任意完整实际解的总移动距离。

松弛解允许没有 Home 的任务子环，也允许相邻边选不同车辆或取货侧。这些未兑现的一致性约束会使下界偏低，不会使下界失效。实现不根据发布顺序删除连接边：晚发布订单可能先于某个尚未执行的早发布订单被处理。

使用无依赖的矩形 Hungarian 实现，整数距离不需要浮点容差。无有限指派时明确报错，不伪装成0；空任务场景三项为0。该下界不适用于只完成部分任务的中间轨迹。

## 如何据此判断优化空间

分别报告 `(actual - lower_bound) / lower_bound`，下界为0时不做除法。三个分项不能直接解释成“其中多少百分比必然可优化”：下界放松了不同约束，其差额包括不可避免的资源、碰撞、层序与多车一致性代价。综合 F 若需要下界，须使用**同一场景既有分母**对 T/R/D 下界加权；不得另换分母后与历史 F 比。

停车候选点应先排除卸货口邻格、装卸格、Home、割点和明显狭窄通道，再用只截至当前的已发布订单统计选点；这属于本项目的启发式方案，不是上述论文的原算法。仅有热度和距离收益仍不足：需要计入重定位空驶，设容量和迟滞，保留安全返库后缀，新单可中断重定位。拥堵导致的退化需要配对轨迹或单因素消融支持，不能直接把某次共享卸货口的负收益全部归因于停车方向。
