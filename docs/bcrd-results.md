# BCRD：有序批次影子派单

BCRD 在当前已发布订单中生成少量合法的有序派单批次，复用真实 SIPP 和执行环境试算，再提交当前最优动作。它不改路径规划器、货架规则、装卸时长或 V4 评分，不撤销已接订单。

本次执行用户提供的 BCRD 技术方案。阶段 A 的逐单账本和两类小实例见 [诊断](bcrd-diagnosis.md)，安全边界见 [影子合同](bcrd-shadow-contract.md)，独立代码检查见 [审核记录](bcrd-code-review.md)。旧 `results/v4/` 保持原样。

## 固定算法与前瞻语义

默认 `bcrd_budget` 使用四候选上限、SIPP 后端、关闭 joint。仅当保底批次可派至少两车，且当前合法订单数至少为可用车辆数三倍，才启动影子搜索。低压力直接采用合法贪心，不依据隐藏到达模式或未来订单决定是否搜索。

候选按确定顺序从贪心、匹配、最老订单、长任务、受限资源和逆序中生成、去重后截断；四候选并不保证每轮都包含逆序。`bcrd_order` 单独固定保底配对，只改变预约提交顺序，用于隔离该机制。

MVP 每个候选完整滚动**当前可见世界**，后续统一使用合法贪心。它是一层当前动作搜索加保底 rollout，不是多层分支搜索，也不预测未来新单。在线代理是可见预计剩余完工、平均响应和未来移动的 50/30/20 加权比值；同一决策的尺度固定为可见保底 rollout 的预测值，完全不调用离线参考分母。已完成历史成本是候选共同常数，省略后不构成整场 F。

每次决策最多480次真实影子 `leg` 调用；扩展量120000在单次 leg 边界检查，允许一条 leg 的软超出；每个预览最多2400仿真步。候选数、调用、扩展、步数和进程CPU均记录。默认没有硬实时 CPU 保证。保底预测失败或预算为零时直接返回合法贪心；正常搜索预算耗尽时保留已经完整评估的最佳动作。真实环境仍按原合同验解和预约。

有限后续1/2批次的消融仅用于验证截断成本：残余订单尚无可信统一尾估计时，预测不会参与评分，直接回退。该深度不是“1/2轮车辆释放事件”，也不是双层分支搜索。暂不加入复杂残余模型或二层分支，先检验MVP的收益与成本。

## 数据纪律与验收

开发种子10–19允许调参；据开发试算选择四候选与队列比例三，冻结协议后才访问留出30–59。留出固定原三模板，90个配对场景、七配置，共630次；泛化使用不同尺寸/订单量及现有五层规则，种子60–69，两配置模板共20个配对场景、三策略，共60次。没有扩到八层，没有改变同面资源粒度。

协议已在结果产生前保存到 [`examples/experiments/`](../examples/experiments/)。所有对照使用SIPP、关闭joint；G0为合法贪心，G1为匹配，G2为选定BCRD；另有顺序、无队列门槛、限制后续1/2批次消融。官方V4时空A*贪心仅用作离线 F 分母，不冒充同后端消融对照。

CPU/墙钟只计原始算法运行；参考预热、独立验解与评分在计时外。失败保留且不产生可比完整 F。均值、配对胜负平、固定4000次bootstrap区间、P90与最坏响应退化、CPU比率一起报告；该区间只对应固定模板实例，不证明任意新地图泛化。

此源码冻结点尚未运行正式留出与泛化；最终数据和结果结论将在后续证据提交中补齐。既有CLI和网页默认策略不变，新策略作为可选实验入口。

## 使用

```bash
agv run --profile v4 --tasks 18 --vehicles 4 --algorithm bcrd_budget --output runs/bcrd.json
agv benchmark-bcrd --protocol examples/experiments/bcrd-holdout.json --output runs/bcrd-holdout
agv benchmark-bcrd --protocol examples/experiments/bcrd-generalization.json --output runs/bcrd-generalization
python scripts/verify_bcrd.py runs/bcrd-holdout
python scripts/verify_v4.py --source-revision 8551943
agv serve
```

网页新增BCRD和相同SIPP后端派单对照；逐候选成本、有效性、拒绝原因和选择解释保存在完整JSON中。路径失败仍是当前预约/预算下的规划尝试失败，不是问题无解的证明。

## 保持行为的影子事件执行

首轮冻结留出在 `90b98ef` 完成：平均F改善0.406%，CPU/G0约3.17，触发事前经济性门槛。因此未依据留出标签修改派单参数，而是在影子内部跳过贪心必定返回空动作的时段。全车忙碌时下一次可派单事件是已承诺任务最早卸货完成；无待派任务时只需完整推进既有回库。真实逐步轨迹仍由原 `advance(delta)` 记录。

新协议 `bcrd-event-*` 在同一源码内比较G2事件模式与G2_stepwise逐步模式，派单候选、门槛、权重和预算完全相同，并与前一版本全部质量指标对账。这是实现等价及CPU复测，复用的种子不能再宣称为第二批未见质量测试。原首轮结果保留，不覆盖。新增单测在不同时间、深度与预算下逐字段比较两个预览，完整派单执行也比较路径、装卸状态、承诺记录和所有非计时解释。
