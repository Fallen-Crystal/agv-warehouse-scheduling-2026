# BCRD：有序批次影子派单

BCRD 在当前已发布订单中生成少量合法的有序派单批次，复用真实 SIPP 和执行环境试算，再提交当前最优动作。它不改路径规划器、货架规则、装卸时长或 V4 评分，不撤销已接订单。

**实测结论：**90个留出场景的综合分数 F 平均改善0.406%，95%配对 bootstrap 区间为[0.069%, 0.737%]；主要收益来自静态积压订单。事件推进保持派单和轨迹一致，将同轮测量的 CPU/G0 从3.16降到1.77。20个尺寸/负载泛化场景平均改善0.535%，CPU/G0为2.28。动态设备场景的区间跨零，共享站场景没有收益，且存在响应尾部退化，因此保留为可选策略，不更改既有默认值。

本次执行用户提供的 BCRD 技术方案。阶段 A 的逐单账本和两类小实例见 [诊断](bcrd-diagnosis.md)，安全边界见 [影子合同](bcrd-shadow-contract.md)，独立代码检查见 [审核记录](bcrd-code-review.md)。旧 `results/v4/` 保持原样。

## 固定算法与前瞻语义

默认 `bcrd_budget` 使用四候选上限、SIPP 后端、关闭 joint。仅当保底批次可派至少两车，且当前合法订单数至少为可用车辆数三倍，才启动影子搜索。低压力直接采用合法贪心，不依据隐藏到达模式或未来订单决定是否搜索。

候选按确定顺序从贪心、匹配、最老订单、长任务、受限资源和逆序中生成、去重后截断；四候选并不保证每轮都包含逆序。`bcrd_order` 单独固定保底配对，只改变预约提交顺序，用于隔离该机制。

MVP 每个候选完整滚动**当前可见世界**，后续统一使用合法贪心。它是一层当前动作搜索加保底 rollout，不是多层分支搜索，也不预测未来新单。在线代理是可见预计剩余完工、平均响应和未来移动的 50/30/20 加权比值；同一决策的尺度固定为可见保底 rollout 的预测值，完全不调用离线参考分母。已完成历史成本是候选共同常数，省略后不构成整场 F。

每次决策最多480次真实影子 `leg` 调用；扩展量120000在单次 leg 边界检查，允许一条 leg 的软超出；每个预览最多2400仿真步。候选数、调用、扩展、步数和进程CPU均记录。默认没有硬实时 CPU 保证。保底预测失败或预算为零时直接返回合法贪心；正常搜索预算耗尽时保留已经完整评估的最佳动作。真实环境仍按原合同验解和预约。

有限后续1/2批次的消融仅用于验证截断成本：残余订单尚无可信统一尾估计时，预测不会参与评分，直接回退。该深度不是“1/2轮车辆释放事件”，也不是双层分支搜索。暂不加入复杂残余模型或二层分支，先检验MVP的收益与成本。

## 数据纪律与验收

开发种子10–19允许调参；据[开发集对照](bcrd-development.md)选择四候选与队列比例三，冻结协议后才访问留出30–59。开发3模板×10种子×9配置=270次；留出固定原三模板，90个配对场景、七配置，共630次；泛化使用不同尺寸/订单量及现有五层规则，种子60–69，两类模板共20个配对场景、三策略，共60次。没有扩到八层，没有改变同面资源粒度。

协议已在结果产生前保存到 [`examples/experiments/`](../examples/experiments/)。所有对照使用SIPP、关闭joint；G0为合法贪心，G1为匹配，G2为选定BCRD；另有顺序、无队列门槛、限制后续1/2批次消融。官方V4时空A*贪心仅用作离线 F 分母，不冒充同后端消融对照。

CPU/墙钟只计原始算法运行；参考预热、独立验解与评分在计时外。失败保留且不产生可比完整 F。均值、配对胜负平、固定4000次bootstrap区间、P90与最坏响应退化、CPU比率一起报告；该区间只对应固定模板实例，不证明任意新地图泛化。

首轮960次运行均完成且通过独立验解；影子事件优化后，再执行440次同种子实现等价/CPU复测。**1400是执行次数，独立未见质量场景仍为90个留出+20个泛化**；不把重复使用的质量种子计作第二次独立检验。开发30个场景与正式质量场景分离。这里使用可复现的 V4 合成任务，没有训练新模型，也没有引入私密数据。

## 留出与尺寸/负载泛化结果

下表的 F 改善是逐场景配对相对改善率的算术均值，正数为好；CPU/G0也是配对比率均值。区间用固定4000次配对 bootstrap，胜/负/平按完整 F 比较。质量结果首次产生于 `90b98ef`，CPU取同一轮 `ad5bce1` 事件版测量；等价审计确认二者全部质量数字完全相同。G0始终为同SIPP、无joint的合法贪心。

| 泛化：中型静态，30单6车 | 10 | 0.988% | [0.196%, 2.025%] | 6/0/4 | 3.53 | 4 |

全部1400次无未完成或验解失败；这里的100%只描述该实验矩阵。留出有13/90个场景P90变差、5/90个场景最坏响应变差；泛化分别为4/20、1/20。完整F改善不能替代尾部服务质量要求。泛化仅覆盖原有3/5层规则和两种中型负载，不代表任意新地图、八层货架或真实车辆部署。

静态留出中，平均T从186降到179.37步，平均D从633.87降到625.80，但平均R从89.91升到92.32步。算法以50%完工权重换取车队更早完成，确实可能推迟一些短单。动态共享站的720次决策全部因低压力直接保底：可同时自由分派的动作很少，在该门槛和该数据下没有搜索收益。动态设备场景只有15次搜索，已发布世界不能预测未来到达，局部更优并不保证完整F改善。

原始表和汇总：[留出](../results/bcrd/event-holdout/)、[泛化](../results/bcrd/event-generalization/)。逐次候选和失败原因保存在 `diagnostics.jsonl`，精选完整JSON固定为各模板首个种子，不以成绩挑选。

## 消融与停止条件

以下消融来自首轮冻结留出（`90b98ef`，逐步影子）；其CPU只能在该轮内比较。所有失败和回退均保留在[原始结果](../results/bcrd/holdout/)中。

| 策略 | F平均改善 | 胜/负/平 | CPU/G0 | P90更差场景数 |
|---|---:|---:|---:|---:|
| G1 静态成本匹配 | 0.051% | 33/22/35 | 1.17 | 19 |
| G2 四候选、队列比例三 | 0.406% | 24/5/61 | 3.17 | 13 |
| G_order 只改同一配对的提交顺序 | 0.011% | 2/0/88 | 2.71 | 0 |
| G_ungated 取消队列比例门槛 | 0.559% | 38/10/42 | 3.88 | 22 |
| G_limited1 后续最多一批 | 0.000% | 0/0/90 | 1.18 | 0 |
| G_limited2 后续最多两批 | 0.000% | 0/0/90 | 1.20 | 0 |

只改预约顺序确实有可利用的耦合，但本组平均收益很小，不能把顺序交换单独包装为主要突破。去掉门槛增加搜索，F仅额外改善约0.153个百分点，却增加CPU与尾部退化；不据留出结果重新挑选参数。有限深度两组均有61次保底预览因 `depth_limited` 残余拒绝，完整有效预测为零，最终全回退；它们主要测到安全拒绝机制，不能推出“浅层规划本身无效”。

首轮G2触发事前规则“CPU/G0>3且平均F改善<0.5%”，所以先优化重复空动作的执行开销，没有增加候选或修改权重。当前事件版不再触发该合取条件，但收益仍小、尾部并非单调改善，故不自动替代默认。未继续增加二层分支、全量ETA、RL/GNN或残余学习模型；下一步若要加入这些，应重新划定未见种子，并先提出可信残余估计及P90约束。

## 保持行为的影子事件执行

全车忙碌时，默认贪心直到已承诺任务最早卸货完成才可能获得可派车辆；全部可见任务已接单后只需执行既有回库。影子跳过这两类区间中的空政策调用，真实逐步轨迹仍由原 `advance(delta)` 完整记录。存在可用车与未派任务、自定义后续政策及深度边界时保留逐步语义。真实在线环境仍逐步推进，正常发现新发布任务。

| 同一轮CPU复测 | 逐步版平均秒数 | 事件版平均秒数 | 配对加速比均值 | 逐步CPU/G0 → 事件CPU/G0 |
|---|---:|---:|---:|---:|
| 静态留出30个场景 | 1.838 | 0.838 | 2.17 | 6.70 → 3.05 |
| 动态设备留出30个场景 | 0.541 | 0.380 | 1.32 | 1.78 → 1.25 |
| 动态共享留出30个场景 | 0.311 | 0.309 | 1.00 | 1.01 → 1.00 |
| 留出合计90个场景 | 0.897 | 0.509 | 1.50 | 3.16 → 1.77 |
| 泛化合计20个场景 | 3.595 | 2.039 | 1.52 | 4.08 → 2.28 |

平均时间的比值与配对比率的均值并不相同：留出平均CPU总量减少约43.2%，而逐实例配对加速比均值为1.50。两者分别列明，不混用。CPU是macOS ARM64、Python3.12.13上的一次计时描述，没有重复计时置信区间或硬实时承诺。事件版最大单次决策CPU：留出0.483秒，泛化1.593秒。

独立[等价审计](../results/bcrd/event-equivalence.json)比较旧→新330对G0/G1/G2行、新事件→新逐步110对G2行，以及20对精选完整结果。剔除CPU/墙钟和事件开关字段后，F/T/R/D、P90、完成率、规划计数、路径、服务标签、任务归属、候选解释的最大差异为零；精选轨迹再次通过独立验解。新协议、原协议和源码哈希全部保留。窄CPU软限附近可能因工作量不同在不同位置截断，正式协议未开启CPU软截断。

## 可解释案例与同步回放

[离线双栏回放](../results/bcrd/replay.html)固定使用静态留出首个种子30，左右同步时间、播放与拖动。它展示真实执行轨迹和已发布任务；顶部完整F是事后评价，不输入政策。

| seed30 | G0 | G2 |
|---|---:|---:|
| T：最后卸货时刻 | 207 | 190 |
| R：平均响应 | 96.278 | 102.778 |
| D：含回库移动 | 690 | 718 |
| P90响应 | 172 | 186 |
| 最坏响应 | 207 | 190 |
| F | 1.000000 | 0.987307 |

时刻0可见18单，G2比较贪心、匹配、最老订单和长任务四批；对应可见代理为1.000000、0.999308、0.987307、1.082364，选择最老订单候选。此静态例中所有订单均已发布，所以后续保底rollout与完整未来重合；动态场景不具备这一条件。实际只改了一次初始批次，最终F下降1.269%，不是四项指标同时改善。

按该场景原分母拆解，T项贡献−0.041063，R项+0.020254，D项+0.008116，合计−0.012693。收益来自较早消除最后交付拖尾，代价是部分订单等得更久、车辆走得更多。逐候选的配对、预测成本、拒绝原因和路由计数都可在JSON复核，无法从本例推出“最老优先永远最好”。

## 使用

```bash
python -m pip install -e '.[dev]'
agv run --profile v4 --tasks 18 --vehicles 4 --algorithm bcrd_budget --output runs/bcrd.json
agv benchmark-bcrd --protocol examples/experiments/bcrd-event-holdout.json --output runs/bcrd-event-holdout
agv benchmark-bcrd --protocol examples/experiments/bcrd-event-generalization.json --output runs/bcrd-event-generalization
python scripts/verify_bcrd.py runs/bcrd-event-holdout
python scripts/verify_bcrd.py results/bcrd/holdout --revision 90b98ef
python scripts/verify_bcrd.py results/bcrd/event-holdout --revision ad5bce1
python scripts/verify_bcrd_event_equivalence.py --validate-traces
python scripts/verify_v4.py --source-revision 8551943
agv serve
```

正式 `benchmark-bcrd` 需要Git源码检出和可编辑安装，以记录完整来源提交及源码哈希；wheel单独安装支持普通运行和网页，不用于这一源码审计命令。已有输出目录拒绝覆盖，复测时选用新目录。复核既有证据时使用对应历史提交，不能把当前源码自动视为旧测量来源。

网页新增BCRD和相同SIPP后端派单对照；逐候选成本、有效性、拒绝原因和选择解释保存在完整JSON中。路径失败仍是当前预约/预算下的规划尝试失败，不是问题无解的证明。

## 工程验证与保留边界

全部160项单元/集成测试通过，包括确实触发搜索的未来任务置换、原观测不变、资源锁、部分装卸、回库、各预算与事件差分。五个实验目录共1400行经[独立重算审计](../results/bcrd/verification.json)核对矩阵完整性、来源Git树、全部产物哈希、配对算术、bootstrap与74份精选轨迹。旧V4的54次成绩及文件未改写，可按历史提交再次审计。

没有修改 `planning/`、`warehouse/` 和 `evaluation/objective.py`；核心仍只依赖标准库。BCRD可以改善部分派单选择，但没有途中撤单或多车联合重排，也不保证全局最优。已有路线安全依赖真实规划器与独立验解，不能由影子代理分数替代。
