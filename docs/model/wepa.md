# WEPA模型与数据边界

`objective_id`家族：`linear-physical-v2-20261024`，配置哈希还区分车数、速度和权重。

公开数据来自WEPAStacks请求记录，固定上游身份、MIT许可和原始字节哈希见 `research/recommended-20261024/data/`。411830条请求的到达时刻、入出库方向、SKU与原始行号保留；仓库位置使用经审核的合成货架映射。初始库存通过窗口前的完整请求前缀重建，假设这些历史操作已完成；不能解释为还原真实工厂的车辆/空间状态。

入库在入口装载1步，到绑定货位服务`2*层数`后增加库存；出库在货位服务`2*层数`后移除库存，到出口服务1步。WMS按库存、层序、入出库独占预约和bay锁动态分配货位；不把任务提前转为固定取货点。相邻车辆不得顶点冲突或对向交换边。完整承诺路线含可中断的兜底返库；发布器闭流后完成所有工作并最终回到专属停车位。

业务profile在结果封套中明确为`wepa`；底图来源是审查过的mixed网格并开放入库口，不声称它仍符合未修改的canonical V9.1规则。独立WEPA规则核验该有限改动；不会放宽旧Scenario校验以接受它。

线性目标`0.5*T/900+0.3*R/900+0.2*D/5400`使用物理尺度：T为最后一项入/出库服务完成时刻，R为请求发布至完成平均时长，D为全部移动含最终返库。默认6车；其他车数会改变距离尺度和objective_id。旧相对F按固定参照归一化，是另一目标。

策略获取的白名单观察仅含已发布订单、已公开闭流状态、库存、货位绑定与现有路线；没有真实关闭时刻、未来订单数或未来任务。可见任务预演复用相同物理实现和主线SIPP，不能成为全局最优或未来订单效果保证。

独立验解器只读模型和完整轨迹，不依赖执行内核/规划器，重新核验位置、边冲突、服务、库存与指标。四个两车微型CP-SAT证书验证机制，不能外推为完整仓库最优性。
