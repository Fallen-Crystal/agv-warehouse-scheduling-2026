# BCRD 派单接口独立审核

审核日期：2026-10-16。范围为 `dispatch/candidates.py`、`dispatch/bcrd.py` 与其影子调用合同，并复核实验输出对诊断字段的解释。审核期间只读源码，未修改策略、规划器、服务规则或离线评分；没有运行留出种子 30–59 或泛化种子 60–79。

结论：未发现阻断当前机制进入冻结实验的未来信息读取、后端混用、总路由调用预算失守、非法批次或遗漏订单预测入选问题。发现的一处诊断归因错误已由实现方修正。此结论是接口和安全审核，不代表 BCRD 已获得留出集性能优势；正式效果以冻结协议的完整配对结果为准。

## 核查结果

| 核查项 | 代码事实与证据 | 判断 |
|---|---|---|
| 在线输入边界 | `bcrd_action` 只接收观测；候选只从已发布、可派订单与可用车辆生成；影子仅以观测重建任务 | 没有把完整真实场景、生成种子或未来订单传入在线策略 |
| 离线评分隔离 | 在线归一尺度来自可见世界的贪心影子预测；正式场景参考分母仅在完整运行后由评分器使用 | 在线代理目标与完整 V4 分数有明确边界 |
| 同后端对照 | BCRD runner 的 greedy、matching、BCRD 均使用 `Environment(..., router_kind="sipp")`，关闭 joint；影子也使用 SIPP | 派单对照没有混入 A*→SIPP 或后缀修复的变化 |
| 候选合法性 | `legalize` 检查车辆可用、任务已发布与可派、车辆/任务唯一、V4 同面唯一；真实执行器继续复核 | 过滤不替代真实合法性检查 |
| 有序批次与去重 | 候选按完整有序配对元组去重；order 消融保留配对集合，只改变预约提交顺序 | 不把相同动作的不同名字当成不同候选 |
| 总路由调用预算 | 每次预览前扣除前序候选的累计 `routing_stats.calls`；影子在每个真实 leg 前检查剩余调用数 | 默认整轮 `max_route_calls` 是硬计数上限，不是每候选重新发放 |
| 扩展与 CPU | 扩展量累计扣减；CPU 从整次决策开始扣减，影子在 leg 边界检查 | 属于软限制，不能描述为硬实时保证 |
| 无效预测 | 入选必须满足 `estimate.valid and estimate.completed`；残余、初始失败、非法动作和预算失败均不能得分入选 | 不靠遗漏难单取得虚假的低成本 |
| 保底尺度 | 第一个候选为合法贪心；若其预测失败立即回退，不用别的候选偷偷改写参照尺度 | 比较使用同一可见参照 |
| 深度消融 | 当前深度统计后续非空派单批次数；浅层残余直接拒绝 | 未把批次深度宣称为已经实现的事件式车辆释放前瞻 |
| 预算终止时的结果 | 保留之前已经完整、合法评估且优于保底的动作；未通过的最后一个候选不能覆盖它 | 最终输出仍经真实 assign 检查 |

默认压力门槛和候选数属于开发集上的经济性选择，不影响上述信息边界。机制单测应显式降低压力门槛以确保真实执行搜索，避免默认门槛调整后测试悄悄只覆盖直接贪心路径。

## 已发现并修正的诊断问题

实验汇总最初以候选的 `reason` 统计 `candidate_rejection_reasons`。该字段表示“最长订单优先”等候选生成解释，实际失败原因在 `preview_reason`，因此预算失败会被错误归因为“distance greedy fallback”等文字。

审核已通知实现方；读回代码确认汇总改用 `preview_reason`，无原因但预测不完整时使用 `partial_forecast`。候选池生成数量与实际完成评估数量也已分别记录。该问题影响失败可解释性，没有改变原候选的执行路线；应使用修正后的汇总重新生成正式实验结果。

## 独立执行的核查

接口审核时完成候选、政策和影子定向测试共 20 项，全部通过（4.146 秒；该计时不作为算法性能结果）。随后实现方将机制单测的压力门槛显式设为零，并增加真实触发影子搜索的未来置换回归，避免测试依赖开发参数。

另行只读运行开发种子 10、11、12 的三个高压力观察：每个观察含五个已发布订单和两个隐藏未来订单。置换隐藏订单 ID、顺序和发布时间后，确保确实发生影子搜索，再比较动作及剔除计时字段后的候选日志，三个样本均逐字节一致；真实观测和路线记录保持不变。

同三个开发观察分别检查整轮路由调用上限 `0, 1, 3, 8, 16, 31, 60, 120, 480`，共 27 个边界实例，所有累计调用次数均不超过指定上限，输出批次均通过合法化检查。低预算时保留贪心；高预算可以保留已经完整评估的改善候选。这些是预算与可见性反例检查，没有读取独立留出或泛化成绩。

## 保留的边界

- CPU 上限无法在一次真实路径搜索内部抢占；候选生成、静态距离建模和状态恢复也不是可抢占工作。需要分别报告完整决策 CPU、扩展超出量及最大决策时间，不能只报告影子内部时间。
- `max_steps` 是每次预览的回放步数上限；整轮硬计数预算由累计路由调用和候选数约束。不要把 `max_steps` 写成所有候选共用的总步数预算。
- 四候选配置可能在去重与截断后不包含 reverse；不能宣称每次 full 搜索都同时覆盖六种启发式。独立 order 消融才保证保留配对集合比较提交顺序。
- 浅层预测不完整时直接回退，尚未使用残余任务的下界评分。若深度 1/2 经常不能完成当前可见任务，这种消融可能主要测到回退比例，应同时披露完整预测率与候选拒绝原因。
- 可见世界的预测可以随着将来订单真实发布而失准。这是在线问题的不确定性，完整真实运行中的 F、P90、最坏响应和失败率仍是最终证据。
- 独立审核没有根据留出成绩修改参数，也没有修改 `results/v4/` 的既有实验。
