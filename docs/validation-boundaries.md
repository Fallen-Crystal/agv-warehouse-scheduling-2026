# 独立验解边界修复（2026-10-17）

本次修复基于 `bd5f26b`，不改变派单策略、目标权重或路径规划算法。

## 轨迹坐标与碰撞

每个轨迹点必须是长度恰为2的列表或元组，两项均须为Python整数（不接受布尔值、小数或浮点形式的整数）。验解器先验证形状与类型，再在内部统一为元组。顶点冲突、对向边交换、静止等待和里程核验使用相同坐标身份；不修改调用方提交的数据。列表与元组是等价的序列化表示，不能使一次停车变成移动或绕过碰撞检查。

## 实际结束时间 B

V9.1成功运行的准备时刻为 `q=max(order_stream_end, max(delivery_end, default=0))`。
从q起，B是轨迹中首次所有车辆同时位于各自H的时刻。成功执行的 `time` 必须等于B。
不信任报告的最终返库事件来确定B；尾部追加停车即使保留正确的返库事件，也会被拒绝。空订单且关闭时刻延后时，B仍不能早于关闭信号。历史V9/legacy的有限回放口径不作追溯变更。

## 零订单口径

T、R及订单响应统计按零任务约定为0，D始终按实际移动计算，E=0.05D。
成功的零订单、零移动执行可以获得有效零分。零订单但发生移动时，实际D、空驶和E保留，`score_valid=False`，F及全部归一化项为null；不能用固定零需求基准的Dref=0作除法，也不能把实际空驶隐藏成有效零分。`comparison_valid`仍表示轨迹执行是否完整合法，不等同于归一化分数有效。此类样本不能进入有效F排名。

## 回归验证

`tests/unit/test_validation_boundaries.py`覆盖小数、布尔、错误形状、混合坐标对向交换、等价静止坐标、尾部停车以及空订单评分。先在原实现中复现失败，再在修复实现中验证。验证入口包括独立轨迹验解、评分和评分复核。

本补丁不将返库耗时加入主目标，不调整50/30/20权重；进一步细分空驶里程和同刻派单排序仍是单独的建模事项。此前实验的“通过独立验解”是当时验解器下的结果，不因此升级为无漏洞证明。
