# 调度与路径算法接口说明

本轮扩展属于可选研究入口。原有算法名称、默认行为、物理规则和正式评价器均保持原口径。

## 正式评价与在线搜索

正式分数为 `F=0.5T/Tref+0.3R/Rref+0.2D/Dref`，越小越好。T为最后一次卸货完成时刻；R为订单发布到卸货完成的平均耗时；D为全车总行驶格数，含最终返库。E=0.05D仅为展示项。参考值由同一场景的原有固定参考算法产生，每个场景内保持一致。

权重是本实验的固定偏好，不能称为文献证明的最优权重。时间、订单体验与行驶资源开销分别对应T、R、D；相关不等于重复。E与D成严格比例，不再重复计权。所有正式比较仅按F选择，不附加“R或P90不得变差”的隐藏限制。

在线搜索只能访问已发布订单、可见车辆状态和已提交轨迹，不能读取未来订单及正式参考分母。当前候选排序与接受使用可见工作量的归一化代理；路径混合算法还使用局部路径代价。这些均不等于正式F。最后必须用完整执行的正式F检验是否真正改善，不能把代理下降宣称为全局最优。

## 订单调度接口

- 输入：当步只读Observation；地图、当前时间、pending、vehicles、已完成历史、订单流是否已经关闭。
- 输出：有序`[(vehicle_id, task_id), ...]`。同批车辆与订单均不重复，遵守同货架格层次优先和资源锁。
- `OwnedDriver`将未分配订单的全局优先序和建议车辆映射解码成合法批次。映射只约束尚未提交的订单，不改派已接单车辆。
- `JointOrderPolicy`以原Portfolio为锚点，对订单移位、车辆改派、车辆归属交换或ACO/PSO候选进行真实路径预演。预演不完整或失败的候选不能获胜。建议计划失效时保留已提交任务，从最新pending重新搜索。
- `priority`只调整同一批次路径预约的先后顺序，不更换订单归属；`combined`同时试验归属邻域与预约顺序。

Portfolio包括原有GA订单搜索、TR/RD代理搜索和批次最小成本匹配。新的assignment是Portfolio之后的联合归属/顺序邻域搜索；aco/pso也是在Portfolio锚点之后增加候选搜索，并非从零替换整个系统。

## 路径反馈与提交

`RoutingOracle`通过原有ShadowState重建已发布工作，预演采用同一执行语义。`RouteFeedback`返回完成性、失败原因、可见预测T/R/D、任务记录、路线与搜索计数；返回的数据为独立副本。

`DispatchProposal`附有可见状态指纹，调用`resolve(observation)`时拒绝过期或非法批次。当前仍由原子命令网关最终校验与提交普通任务对列表；指纹检查不能代替原网关的车辆、订单、层次与资源检查。路径仍需原生约束解码和独立轨迹验解。

唯一runner新增可选`on_assignment(before, feedback, after)`回调。after在提交后重新获取，不能复用提交前车辆可用状态。实际派单部分失败，或实际车辆/取货点/卸货完成时刻与预演不一致时，新策略记录差异并取消后续建议计划。已经成功提交的任务保持不变。

研究入口以环境类注入相同的路径规划器到真实世界和影子世界。旧预演器要求可继承的环境类，不能注入任意工厂对象；首轮联调曾暴露此限制，失败记录与源码快照已保存。
最终接口仅提供整数诊断计数，不在传给策略的环境类上挂接真实路由器或完整场景指针。动作盖章也不再重复创建影子环境。这两项接口整理后，12份开发集代表轨迹与整理前逐项哈希一致。

## 路径混合算法

所有车辆仍在四邻接网格上移动或等待，不加入斜向、曲线或DWA。

| route参数 | 空间路线搜索 | 时间与预约解码 |
|---|---|---|
| sipp | 原有搜索 | SIPP |
| astar | 原有搜索 | 时空A* |
| aco_sipp | ACO信息素引导的空间A* | SIPP |
| pso_sipp | PSO搜索空间代价场，A*解码 | SIPP |
| aco_astar | ACO信息素引导的空间A* | 时空A* |
| pso_astar | PSO搜索空间代价场，A*解码 | 时空A* |

混合算法先保留基准可行路径。只有基准路径耗时超过“静态最短距离＋服务时间”，即存在等待或绕行时才搜索备选通行格集合。每段最多12次空间提案、4次新的时间路径解码。备选仍需满足顶点冲突、对向换位冲突、装卸占位、交付口专用和专属车位等全部约束。

ACO采用信息素蒸发与优秀路径强化；PSO粒子编码七维非负空间代价参数，A*将参数解码为实际网格路径。这是本仓库的有限预算混合启发式实现，不是经典ACS或某篇仓库论文的完整复现。PSO优化代价场不意味着车辆在连续空间运动。

局部路径排序为“耗时比＋0.4×移动格数比＋0.02×已预约路线邻近风险”，允许的额外耗时搜索窗口最多`min(4,ceil(0.1×原耗时))`步。这些是搜索机制，不是新仓库物理规则或正式评价权重。局部选择可能影响后续车辆，因此不能据此保证全场F下降。无可用改进时返回基准路线。

研究路由的calls计数包含内部空间/时间子搜索。旧预算守卫在外层leg边界检查，因此混合方法的子调用计数可能在最后一个leg超过名义阈值；不能宣称对子调用有严格硬上限。空间/时间提案本身有明确有限上限，保留实际计数和CPU时间。原生A*/SIPP每次外层leg只递增一次，原有调用预算语义不变。

全段都做群体搜索的预试验因计算成本被中止，部分轨迹与源码快照保留。最终开发版采用拥堵触发；这可能漏掉“当前等价但对未来交通更有利”的预防性路线。

## 复现入口

在项目根目录设置`PYTHONPATH=src`，使用Python 3.10及以上版本：

```powershell
python scripts/run_path_research.py --orders assignment --route sipp --output runs/joint-demo.json
python scripts/run_path_research.py --orders aco --route pso_sipp --regime dynamic --output runs/hybrid-demo.json
```

复现开发集冻结候选时，显式提供已知的static/dynamic实验类别；不根据未来订单自动推断类别。当前平均F较好的研究候选使用`recommendation.json`，统一对照使用`unified-control.json`；两者没有覆盖原冻结文件。

```powershell
python scripts/run_path_research.py --selection results/path-study-20261022/selection.json --regime static --output runs/selected-static.json
```

`--input`可读取保存的场景或包含scene的回放文件。输出含场景、完整轨迹、正式分数、路径计数与预演/提交反馈。输出文件必须使用新名称。

批次之间仍待命，全部批次完成且订单流已关闭后最终返库。新算法不更改这条规则。SIPP只在固定其他预约的单段问题上提供较早到达搜索；这些调度和路径组合没有全局F最优性或统一近似比保证。
