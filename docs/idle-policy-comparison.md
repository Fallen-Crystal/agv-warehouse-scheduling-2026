# 卸货口附近待命与途中可接单返库：论文与配对实验

## 结论边界

两种方案都有文献背景。当前模型下，合理区域待命有减少空驶的优势，稀疏订单最明显；共享出口批量订单可能出现响应或F退化。不能以“少走返库路”推出所有指标全局最优。当前探索性实验不支持宣布某个纯策略普遍优胜。

生产仓库代码没有修改；当前V9.1规则仍保留。实验使用同几何/层序的V9兼容场景承载两个研究策略，因为生产V9.1有意只允许待命合同。显式订单流结束及所有车最终返H在两种研究方案中一致。

## 两个方案如何公平定义

A：卸货后先退出D，沿已有安全兜底路径，到本单D的曼哈顿距离2—3格的普通通行地面尝试待命；排除所有D的直接出口邻格、作业区和H。与其他已接受完整路线发生预约冲突时不强停，沿安全返程让行；若无法在该范围停留可继续返程。没有新增固定候车位，也不读取未来订单。

B：卸货后直接执行回自身H的路线，但车辆始终可接单；新单到达时允许从返程当前位置改道，不要求先到H。独立复核中B实际有104次下一单在尚未回H时接入，避免把对照误做成强制返到位。

两者使用相同已发布订单距离贪心、SIPP、派单顺序规则、货位/层/交付点、取货2l/卸货1步、.05D能耗代理；唯一处理因素为空闲策略。生成器、生产源码没有修改。场景同时满足最后一批发布的关闭事件；关闭且全部卸货后，两者都最终返库，最终里程计入。

## 冻结实验设计

4种地图×3类工况×种子101/102/103，共36个配对设置、72次执行。密集静态为6车12单，稀疏为4车12单、每100步1单，共享出口批量为8车12单、每250步4单并切换热点。双排3层，单排1层。原始完整场景与SHA在A/B之间相同，顺序由固定种子打乱。

F按原权重50/30/20，但这次研究用同场景固定B（SIPP返库贪心）的T/R/D作为共同分母，B=1。它与生产包A*参考分母不同，不能拿本研究F横比旧报告F；A/B均使用同一参照，没有随候选换分母。能耗E=.05D不重复入目标。

计算保护为最后释放后2000步，只是研究终止保护，失败须报告，不是新物理截止期。本次72/72完成且独立验解通过，没有截断失败。每个设置只有3个独立种子，相同种子跨地图产生相关任务结构，36设置不能视为36个独立实仓样本；未做显著性或总体最优宣称，也没有权重扫参。

## 为什么没有单一绝对答案

忽略其他车、障碍随时间变化及任务换车时，当前待命位置p、返程中位置x、下一取货点q，返程已走l格：

```
留在p再取货：空驶 d(p,q)
先返程再改道：空驶 l+d(x,q) >= d(p,q)
新单出现后的到达耗时：待命 d(p,q)，返程 d(x,q)
```

第二项不更短，却可能在新单出现前已经把路走完，因此接新单后更快。例：一条通道D外位置10、H在0；空闲10步后新任务在0，待命方案接单后还需走10格，返库方案已到0，两者取货前总空驶都为10格。若下一任务在10附近，则原地待命通常更省路。多车时又会发生选车、选侧、占道变化，上面的单车不等式不保证系统总D关系。

此外本模型E只按移动格数估计，不计待机功耗；T只到最后卸货，B才包含最终返H。A可能省D而延后B，必须同时报告。不能用距离能耗代理直接声称真实电池节能百分比。

## 建模建议

若继续当前方向，可保留“安全近D待命”为主方案，将“可中途接单返库”为对照；不要写成任何新单都必须返H后才能接。待命区域要排除D、D直接出口和作业区，容量/预约不满足时允许让行，所有批次结束后最终返库保持。

共享口拥挤、需求偏向H侧或响应优先的场景，应允许方案B成为更合适的选择；不应为了减少空驶强留D旁。更进一步可以把待命/返库作为算法决策，用已知积压、历史需求分布和安全容量选择；这增加可选行为，不等于某个在线启发式就能保证全局最优。

本轮不自动改生产规则或仓库。若需要正式论文效果结论，下一步应冻结调度算法后增加独立种子、真实/更广到达过程和更合理的安全候选区域，尤其加测共享口高负载；不必为此先做权重比较实验。
