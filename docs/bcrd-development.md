# BCRD 开发选择记录

本页只使用开发种子10–19。参数与正式协议已在源码提交 `90b98ef` 冻结，随后在同一源码上重放270次开发运行；冻结前的探索输出保存在本机 `runs/`，不当作未见留出成绩。所有配置在三模板、同一SIPP且无joint、同一输入上比较，每项10个种子，全部完整成功并独立验解。

`G2` 为四候选、队列/可用车比例门槛三；`G_full6` 为六候选且不设队列比例门槛；`G_ungated` 为四候选无比例门槛；`G_ratio2` 比例门槛二。所有搜索仍要求保底能给至少两车派单。`G_order` 仅交换保底配对的提交顺序；`G_limited1/2` 最多追加1/2个后续非空派单批次，残余任务未结算时拒绝预测。

正值表示相对相同SIPP/no-joint的G0分数下降，先对各个固定场景计算相对差，再取均值。总体每个实例等权（本设计也与三模板等权一致）。CPU比率为每个配对比率的均值，单次计时仅作经济性估计。

选择原因是：六候选并未稳定改善完整得分；弱积压的动态设备场景中，已发布世界的局部最优可能因后续新单而失准。比例门槛三保留开发静态收益，减少动态无效或不利试算，把总体效果从四候选无门槛的约0.35%提升到约0.71%，CPU比率从约3.92降到2.91。它只使用当前合法队列与可用车，不读取到达模式、未来订单或离线分母。

这属于开发选择与解释性假设，不是因果消融证明或留出收益承诺。之后不依据留出或泛化成绩调整参数。旧默认策略不替换；正式检验同时报告F、P90、最坏响应和CPU，失败不删除。数值来源为 [`development/summary.json`](../results/bcrd/development/summary.json)，完整270行、诊断及精选轨迹均保留。
