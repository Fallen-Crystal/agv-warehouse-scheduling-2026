# 小规模最优性对照（2026-11-03）

本文回答一个正式 240 次实验没有回答的问题：**在极小静态实例上，当前在线贪心和联合重规划离真正的最优有多远？**

## 1. 方法

`oracle.py` 对不超过 5 单、不超过 2 车的静态实例枚举：

1. 每个任务分给哪辆车（`vehicles^tasks`）；
2. 全局任务顺序（`tasks!`）；
3. 按顺序在真实 `Environment` 中调用 `assign()`，保留顶点/对向交换预约、装卸服务和返回停车位约束；
4. 取平均响应时间最小、其次 makespan、再次总移动的可行轨迹。

因此它是在 **“不主动插入空等动作”的调度类内** 的精确搜索，不是完整 MAPD 的全局最优证明；规模限制也使它只能做小例子。运行：

```bash
python3 benchmark_oracle.py --seeds 10
```

结果保存在 `oracle_small_results.json`；全部 oracle 轨迹都通过独立 `validation.py`。

## 3. 解释

- 小实例的差距主要来自 **t=0 时把哪两单配给同一辆车**：先接最近的任务不一定得到最好的两单组合。种子 1 中贪心把 3→2、0→1 配对，oracle 改为 3→0、2→1，平均响应从 25.5 降到 24.0。
- 联合重规划只能在已接任务之间改路线，不能换任务归属，所以能修复一部分路线次序（种子 2、5），不能修复错误的初始配对（种子 0、1、9）。
- 精确匹配的静态距离矩阵没有把后续任务和拥堵纳入，在 4 单小例上反而更容易做出差的组合；这与正式实验中“匹配在部分场景变差”的结论一致。
- 这些数字 **不能** 外推为 30/40 单场景的差距，也不能证明联合算法全局最优。它只说明“当前启发式在极小例上有 0–6% 的可解释差距”，与报告中的局限说明一致。

## 4. 边界

- 只支持静态、release=0、≤5 单、≤2 车；动态和较大规模不走该 oracle。
- 只枚举“不主动空等”的调度类；A* 仍会在路径内部等待/绕行。
- 这是离线分析工具，不参与正式 240 次在线基准，也没有用未来订单为在线策略提供信息。
