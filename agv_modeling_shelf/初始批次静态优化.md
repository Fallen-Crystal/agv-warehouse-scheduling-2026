# 初始批次静态优化（2026-11-03）

## 1. 问题

静态场景在 t=0 就能看到全部订单，但原策略仍然按“当前最近”逐单贪心。oracle 对照显示，4 单/2 车小例的主要差距来自**初始把哪几单配给同一辆车**；联合重规划只能改路线，不能改任务归属，因此修不回来。

## 2. 方法

新增可选的静态批次规划 `initial_planning.py`：

1. 仅当场景所有订单 `release == 0` 时启用；动态场景直接返回空，避免用未来到达信息做离线回放。
2. 以贪心初始分配为基准，生成有限候选：交换两辆车的已分配任务，或把一辆车的任务替换成一个未分配任务。
3. 先用便宜的贪心 rollout 给候选排序；取前 4 个，并把贪心基准强制加入。
4. 对候选池用**与主程序一致的 greedy + 联合重规划循环**回放到底，按平均响应时间、makespan、移动量选择。
5. 基准始终在候选池里，因此在这批候选内不会比原联合方案差；`optimized.run(..., initial_rollout=True)` 显式开启。

它不改变默认行为，也不参与正式 240 次在线实验。

## 3. 结果（10 个种子，静态，单位步）

| 布局 | 原联合 | 静态批次 | 平均改善 | 单次耗时 |
|---|---:|---:|---:|---:|
| 小型静态宽通道 | 29.308 | 28.625 | **2.26%** | 约 0.55 秒 |
| 小型静态窄通道 | 30.675 | 29.808 | **2.75%** | 约 0.56 秒 |

逐种子没有变差：宽通道 5 胜 5 平，窄通道 7 胜 3 平；改善最大的种子从 31.17 降到 29.00、从 32.00 降到 29.00。

数据见 `initial_batch_results.json`，复现命令：

```bash
python3 benchmark_initial_batch.py --seeds 10
```

页面中对应“联合 + 静态首批批次”选项：静态场景走批次候选，动态场景自动回退到联合重规划。

## 4. 为什么不是默认

- 只对静态全可见场景有效；动态场景被显式排除，不能拿未来订单做 rollout。
- 单次静态运行从约 0.05 秒增加到约 0.55 秒；课程演示可以接受，但不适合作为所有场景的默认。
- 仍是有限候选加启发式回放，不是全局最优；oracle 只用于小例对照。

## 5. 与 oracle 的关系

小例 oracle 说明了“初始配对”是真实瓶颈；本方法把它变成一个**可执行的静态批次选择器**，并用联合策略回放来避免只优化贪心 rollout 造成的错配。它不是 oracle 的在线化，也不声称大场景最优。
