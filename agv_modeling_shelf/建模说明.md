# 仓库多 AGV 取送任务调度：静态与动态建模说明

版本：2026-10-14，第一版可运行模型。用途：建模部分的讨论、报告撰写与算法交接。本文定义问题；附带的贪心策略与时空 A* 是运行模型的参考实现，不代表最终创新算法或全局最优解。

## 1. 我们研究什么

仓库内有固定货架、可通行的通道、交付点及车辆专属停车位。每个新任务指定一个货架格，车辆选择其旁边合法位置停靠装载，再到交付点卸载。需要共同决定任务由哪辆车执行、执行顺序、从哪侧取货，以及车辆的时空轨迹。

货架格是货架实体的占位，车辆沿货架之间的通道行驶，在相邻取货服务点停车完成取货。装卸机械过程以服务时间表示。这里研究运输零件的车辆，不模拟顶升并搬运整个货架。

最短路只能回答单辆车怎样走得近。多车调度还要处理同一通道被占用、装卸点被占用、车辆对向行驶及任务负载不均衡。例如，最短路径长 8 步却需要等待 5 步，另一条路径长 10 步且无需等待，则后者到达更早。实际选择仍需路径规划和实验验证。

## 2. 两种任务设定

**静态版**：所有任务在调度开始时已知，释放时间均为 0。任务可以分别执行，也可以同时分配给不同车辆；“同时已知”不等于“同时开始取货”。即使订单已知，车辆仍可在每个时间步重新安排尚未指派的任务。

**动态版**：任务在不同时间出现。调度时只能读取已经释放的任务，不允许查看未释放任务的位置、释放时间、任务编号列表、总任务数及生成随机种子。环境内部保存完整输入用于仿真和事后验证，完整输入文件不是在线策略的观测。

附带样例让每批 3 个任务分别在第 0、15、30、45 步出现；这只是可复现的演示到达模式，不是假定所有真实订单必须这样出现。可以改变输入中的 release，构造随机到达、集中到达或需求热点变化。固定地图和任务位置、只改变 release，可以检查两种运行模式，但不能据此宣称某算法更优。

## 3. 基础假设与边界

1. 仓库表示为二维四邻接网格。每辆车在一个时间步内移动到上下左右相邻格，或留在原格；不允许斜向移动。
2. 车辆同质、速度相同，容量为一个任务的货物。每个任务的货物被视为一个运输单元，不拆单、不合单。
3. 货架与墙体固定不可通行。订单指定货架小格，车辆可选择其四邻接的合法通行位置装载，停靠位置与交付点均不设在停车位。同一货架小格的不同合法侧可以独立、同时装货；假设各侧装载装置可独立服务、货物充足，暂不模拟库存扣减。
4. 装载、卸载持续正整数个时间步，期间车辆持续占据对应服务点。各任务可以有不同服务时间，默认均为 1 步。
5. 每辆车从专属停车位出发，其他车辆不能进入该停车位。卸货后允许立即接新任务；没有新任务时返回停车位。任务全部完成后，各车返回停车位结束仿真。
6. 任务指派成功后，从指派到卸货完成均锁定车辆；本版不允许取消未取货的已指派任务。卸货后的返回段可被新任务的路线替换。
7. 避碰按离散网格点机器人处理：禁止同一时刻同格，禁止在一个时间步内交换相邻位置。它不等价于真实车辆尺寸、转弯半径、连续运动的安全校验。
8. 暂不考虑电量、充电、故障、车速差异和零件库存不足。全程有统一仿真时限 H，超过时限未完成或未返回停车位均记录为失败。

这些假设用于控制第一版工作量。能体现调度难点的关键是：任务顺序、容量限制、装卸占位、时空冲突、动态信息可见性及一致的评价指标。增加约束应有明确实验问题，不能仅靠增加参数证明创新。

## 4. 符号与输入

| 符号 | 含义 | 对应输入或日志 |
|---|---|---|
| G=(V,E) | 可通行节点和四邻接边 | width、height、blocked |
| K | 车辆集合 | homes 的下标 0…m−1 |
| J | 任务集合 | tasks；id 必须唯一 |
| h_k | 车辆 k 的专属停车位 | homes[k] |
| b_j、d_j | 目标货架格、交付位置 | shelf、delivery |
| q_j | 车辆选中的装货停靠位置 | events中的pickup_point |
| r_j | 任务释放时间 | release |
| s^p_j、s^d_j | 装载、卸载时间 | pickup_service、delivery_service |
| H | 仿真最大时刻 | horizon |
| a_kj∈{0,1} | 任务 j 是否由车 k 执行 | assignment 中 vehicle、task_id |
| S_j | 任务被成功指派的时刻 | assigned_at |
| P_j | 装载开始时刻 | pickup_arrival |
| D_j | 卸载开始时刻 | delivery_arrival |
| C_j | 卸载完成时刻 | delivery_end |
| x_k(t) | 车辆在整数时刻 t 的位置 | paths[k][t] |

所有时间均为整数“步”，距离为网格边数；目前没有标定实际秒数和米数。需要实际单位时，应先规定一格长度及一个时间步时长，再统一换算，不能默认 1 步必然是 1 秒。

## 5. 决策与优化目标

需要选择：车辆与任务的分配a、各车的任务执行顺序、各任务的装货停靠位置q，以及时空轨迹x。事件时间由实际轨迹及服务时长决定，不能仅用静态最短距离替代。新生成订单指定货架格b，不固定取货停靠点；旧输入中的固定pickup仅作为兼容模式。

静态版主目标为最小化全部任务卸货完成的时间：

$$\min C_{\max},\qquad C_{\max}\ge C_j\quad(\forall j\in J).$$

动态版建议以平均任务响应时间为主目标，即任务出现到卸货完成的平均耗时：

$$\min \frac{1}{|J|}\sum_{j\in J}(C_j-r_j).$$

这里动态目标在给定完整评测场景后计算；在线策略无法预先使用未来 J。对同一个固定场景，平均完成时刻与平均响应时间只相差固定常数，但响应时间的解释更直观。任务为空时指标约定为 0。

无论使用哪个主目标，**全部任务完成且轨迹满足约束**是成功的前提。失败场景的“已完成任务均值”只是诊断值，不能混入成功场景均值，使只完成少量容易任务的策略显得更好。

辅助指标：总行驶步数、行驶阶段等待步数、装卸占位步数、空闲步数、成功率和算法耗时。完成时刻 Cmax 不包括最后返程；环境停止时刻 time 包括最终返程。两者应分别报告。

## 6. 约束体系

以下为“分配、事件时间和实际轨迹”的约束模型，可以用于仿真验收。它不是已经线性化的 MILP，也不是只列目标与静态距离的简化模型。

**每个任务恰好由一辆车执行：**

$$\sum_{k\in K}a_{kj}=1,\qquad a_{kj}\in\{0,1\}. $$

动态策略只能在 r_j≤t 后决定该任务的指派。同一批中一个任务、一个车辆最多各出现一次。

**释放与取送顺序：**

$$S_j\ge r_j,\quad P_j\ge S_j,\quad D_j\ge P_j+s^p_j,\quad C_j=D_j+s^d_j. $$

仅有这些不等式还不够，必须将时间与执行车辆的轨迹关联。若 a_kj=1，则：

$$q_j\in\mathcal{P}_j,\qquad\mathcal{P}_j=\{v\in V:\|v-b_j\|_1=1,\ v\notin\{h_k:k\in K\}\},$$
$$x_k(t)=q_j\quad(t=P_j,\ldots,P_j+s^p_j),$$
$$x_k(t)=d_j\quad(t=D_j,\ldots,C_j).$$

在服务区间 [P_j,P_j+s^p_j) 和 [D_j,C_j) 的每一步都禁止移动。区间包含的端点位置也必须相同，因此持续 1 步的装载需要连续两个整数时刻位于取货点。取货点与交付点之间的实际移动由下述运动约束保障。

同一货架格允许多辆车在不同合法相邻格同时装货，不再要求装载服务区间互斥。每个停靠格同一时刻仍只能有一辆车，由下述车辆避碰约束保证。货架格属于障碍，车辆始终停在所选相邻格q上。

**运动与地图：**

$$x_k(0)=h_k,\quad x_k(t)\in V,$$
$$x_k(t+1)=x_k(t)\quad\text{或}\quad(x_k(t),x_k(t+1))\in E.$$

同时禁止 x_k(t)=h_l（k≠l）。

**顶点冲突：**

$$x_k(t)\ne x_l(t)\quad(k\ne l).$$

服务车辆、等待车辆、空闲车辆都要检查，不只是移动中的车辆。

**对向边冲突：**

$$\neg\big[x_k(t)=x_l(t+1)\ \land\ x_k(t+1)=x_l(t)\big]\quad(k\ne l).$$

这避免两辆车在一步内迎面交换位置。不同车辆前后沿同方向通过通道，在满足上述占位规则时允许。

**车辆容量与执行锁定：** 若 j、q 分配给同一辆车，则本版要求：

$$C_j\le S_q\quad\text{或}\quad C_q\le S_j.$$

因此一辆车不能同时执行两个任务，也不能装着上一单去取下一单。它可以在卸货完成的同一时刻被指派下一单，不要求中间先回停车位。本版锁定从指派开始，比只约束载货区间更严格。

**终止：** 存在 T≤H，使所有 C_j≤T 且所有 x_k(T)=h_k。若参考规划器在时限内找不到路径，不能据此证明数学问题无解，只能报告该次策略与规划器组合未成功。

## 7. 状态与决策时序

车辆状态：idle → to_pickup → loading → to_delivery → unloading → returning → idle。returning 状态可以直接接新任务并转入 to_pickup；装卸完成的边界时刻立即更新状态。

任务状态：unreleased → pending → assigned → loading/transporting/unloading → completed。环境日志分别记录成功指派与完成事件；pending 列表只含已经出现且尚未指派的任务。

每个整数时刻先观察、再提交指派，然后所有车辆同时执行一个时间步，最后更新装卸完成状态。下一步观察中出现新释放任务。这样 r_j=t 的任务可以在时刻 t 指派。

第一版采用每一步一个决策机会，以免新到任务被跳过。空批次是合法动作，表示本步不指派；尚未指派任务继续保留。没有任务时车辆仍按既定返回路径执行或在停车位等待。

## 8. 数学模型与参考求解器的区别

本模型允许满足约束的所有合法轨迹；附带实现采用预约表与时空 A*，按提交顺序逐车规划，既有轨迹具有优先权。新任务一次预约到取货、交付和返程，后续可以替换自己尚未执行的返程。其他车辆的既定路线在这次规划中不被改动。

这使策略可以安全接入，但也限制了求解器探索的范围。它不是全局多车联合最优规划器；可能存在可行的联合方案，而固定优先规划找不到。优先顺序和时限应作为实验配置记录，不能把规划器搜索失败说成问题必然不可行。

已经实现的是环境和简单策略；匈牙利算法、DQN、预测模型、遗传算法均未在本交接包内实现。固定订单和动态订单都可调用同一套接口。未来换路径规划器时，仍需用独立验证器验收。

## 9. 算法同学应拿到什么

交接文件包括：本说明、算法接口说明、Python 环境、固定简单策略、静态/动态输入样例、完整执行轨迹与独立验证器。

算法同学负责根据 observe 的信息生成车辆—任务指派对及提交顺序。匈牙利算法可根据当前可接单车辆和 pending 任务构造代价矩阵；DQN 可选择有限种代价权重或调度策略，再调用匹配方法。若有 m 辆车和 n 个任务，可以部分匹配，不要求每辆车都接单；未匹配任务继续等待。策略选择和路径可行性是不同步骤，必须处理 accepted=False。

为避免“策略效果”与“规划器效果”混在一起，首先应固定地图、输入任务、路径规划器、决策频率和服务时间，比较不同调度策略。随后再单独改变规划优先级或规划器做消融。动态实验中如果引入预测，只能用过去数据或训练集拟合，不能读取当前测试场景的未来订单。

## 10. 建模部分的报告写法与贡献

报告建议顺序：问题与场景 → 假设和理由 → 符号及目标 → 约束 → 状态与时序 → 仿真实现 → 模型验证 → 局限。地图示意和一条任务的时间线能帮助读者理解，不需要把所有代码逐行解释。

建模贡献可以据实写为：建立取送任务与多 AGV 时空运动的约束模型；实现静态和动态任务释放机制；定义可见状态、任务锁定和返程重派规则；实现独立轨迹验证与统一指标；提供可复現场景和算法接口。最终分工应按两人实际完成情况更新。

后续创新方向优先围绕一个可检验问题：**拥堵或未来需求估计能否改善动态响应时间，并且不会以大量行驶距离或计算耗时为代价？** 先建立强固定策略基线，再研究学习策略。这个交接包完成建模基础，不预先承诺深度强化学习一定更好。

## 迎面避让的参考求解行为

禁止顶点碰撞和迎面交换是模型约束；等待、绕路、进入侧边空位是合法动作，允许车辆暂时远离目标再继续。当前时空A*依据先行车辆的已预约路线规划后行车辆。接单发生在运行过程中也会考虑已有轨迹，不是所有车辆必须统一规划后才开始运动。已接任务的路径保持锁定，尚未实现途中联合重规划；无错车空间时可能拒绝本次规划，不等于证明整个任务无解。演示见《车辆迎面避让演示.html》。
