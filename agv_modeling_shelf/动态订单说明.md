# 第二项改进：动态订单到达与需求分布

实现范围：在第一版的固定批次到达基础上新增三种到达方式、三个需求偏置方式；仓库页面的参数独立选择，通过本机Python服务即时运行。未实现学习策略、预测算法或新的匹配算法。

## 四种到达方式

所有时间单位为步，任务编号按生成顺序排列。第一个任务在第0步出现。

| arrival 参数 | 页面选项 | 释放规则 | 12单时的示例 |
|---|---|---|---|
| batch | 每15步3单 | r_j=15⌊j/3⌋ | 0,0,0,15,15,15,30,30,30,45,45,45 |
| uniform | 每5步1单 | r_j=5j | 0,5,10,…,55 |
| irregular | 不规则间隔1～9步 | 第一单0，之后增加独立均匀整数间隔1…9 | 给定种子可复现 |
| burst | 每30步6单 | r_j=30⌊j/6⌋ | 前6单0，后6单30 |

这里“不规则间隔”是离散均匀间隔，并非泊松过程。后三种模式设计的长期平均到达间隔约为5步/单，但有限任务集的最后释放时间、平均释放时刻及瞬时积压不同；不能声称工作负载完全一致。做对比时应同时记录任务数、释放序列、最后释放时刻及运行时限。

静态模式强制所有 release=0，页面禁用到达方式选项。需求分布仍可用于静态任务。

## 四种取货需求

| demand 参数 | 含义 |
|---|---|
| balanced | 每单随机选择左右侧货架，各侧概率50% |
| left_hotspot | 每单取自左侧的概率80% |
| right_hotspot | 每单取自右侧的概率80% |
| switching | 前半批任务以80%概率取自左侧，后半批以80%概率取自右侧 |

80%是采样概率，不保证12单中恰有80%来自热点。switching 的切换依据任务生成顺序，前半数量向上取整；它不是固定在某个时刻发生的热区切换。

基本位置、到达间隔及热点偏置使用独立随机流，由 seed 可复现地派生。改变 arrival 保持同一需求配置下的取货点、交付点和服务时间完全一致；改变车辆数和通道配置也不改变同一尺度下的任务位置。改变仓库大小会改变坐标范围，不再是同一位置集合。

## 算法接口

```python
scenario = example(mode='dynamic', size='medium', vehicles=6,
                   layout='wide', task_count=24, seed=5,
                   arrival='irregular', demand='switching',
                   delivery_pattern='shared', horizon=600)
```

新增参数只是场景生成器输入，observe/assign/advance/result保持原来的调用方式。在线策略仍然只看到已释放任务；完整输入和页面中的完整轨迹属于评测或事后查看信息，不允许策略读取页面接口来获取未来订单。

default arrival='batch'、demand='balanced'，保留第一版任务和结果。horizon可通过生成器设置，网页允许60～1800步；车辆1～8，任务0～60，种子0～999999。超限时明确拒绝，不偷偷替换参数。
