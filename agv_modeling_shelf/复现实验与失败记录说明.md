# 基础版新增三项：复现实验、批量运行与失败记录

本文说明继承的复现实验功能；当前目录为agv_modeling_shelf，取货规则已扩展为货架任选侧，详见《货架取货改动说明.md》。没有加入待命或紧急任务。原方案A及独立紧急任务版保留不变。

页面采用直白名称：“平均订单完成耗时”是订单出现到卸货完成；“平均等车接单时间”是订单出现到成功分配给车辆。前者已经包含后者。字段mean_flow_time和mean_dispatch_wait以及计算值保持不变。

“取货位置分布”选项直接标注每单来自左右货架的概率。原“热点80%”表示每单有80%概率在该侧取货，并非这侧货架占仓库面积的80%。前半订单偏左、后半偏右按订单生成顺序划分，两阶段的偏向概率各为80%。

## 1. 完整场景保存与加载

运行show_warehouse.py，生成场景后点击“下载完整场景与结果JSON”。保存的是实际地图、停车位、完整任务位置、释放时间、服务时间、运行时限、配置和执行结果，同时附上场景SHA256校验值。

选择保存的JSON，再点击“读取场景并重新运行”。重跑使用文件里的具体输入，不依赖当前下拉选项或重新生成种子；文件中的历史结果不会当成新的执行结果。页面使用原距离参考策略重新运行，换算法后相同场景可以有不同结果。

导入后的下拉选项仍保留之前的设置，页面明确提示其不代表导入文件。之后点击“生成并运行”则按下拉选项创建新场景。支持此前样例中的纯Scenario JSON及包含scenario的结果JSON；紧急版字段不属于本版本，不能混用。

为了控制网页计算量，导入文件不超过10MB、地图不超过30×30、8辆车、60个任务、1800步。程序接口可以读取合法场景，不受这组网页上限限制。如果手动修改包含校验值的文件，应更新校验值或将它作为新的纯场景文件，不能假称原场景未改。

算法同学可以直接使用：

```python
from scenario_io import load_scene, save_scene
from baseline import run
scenario = load_scene('完整仓库场景.json')
result = run(scenario, policy=my_policy)
save_scene('我的结果.json', scenario, result=result)
```

完整场景是评测驱动输入，不是在线策略观测。动态策略仍只能使用observe中的已释放订单。

## 2. 多种子批量实验

网页选择公共参数，输入起始种子和运行数量（1～20），点击“按当前参数批量运行”。例如起始0、数量5，对应种子0、1、2、3、4。网页不改变已经显示的单场景地图；批量完成后下载完整结果JSON及统计CSV。

也可在PyCharm右键运行batch_experiments.py，默认运行动态、不规则到达、种子0～4。结果保存到batch_results的独立时间戳子文件夹，避免覆盖已有运行。里面有逐次runs.csv、统计summary.csv、配置与代码摘要manifest.json，以及每次实际场景、轨迹、每车/每单CSV和失败记录。

mean/std指标只使用成功运行；std为样本标准差，只有一个成功运行或没有成功时为空。成功率与平均完成率包含失败运行；不能只报告成功样本均值而隐去失败数。runtime_seconds是环境执行耗时，含策略调用、路径规划及结果统计，不是纯算法计算耗时。

这个入口按多个任务种子重复同一套参数；仓库规模等不同参数组可分别运行。当前网页只提供原距离规则，算法同学可通过policies参数批量比较多个策略：

```python
report = run_batch(config, [0, 1, 2], policies={
    'distance': greedy_action,
    'my_algorithm': my_policy,
}, output_dir='一个尚不存在的输出文件夹')
```

每个种子只生成一次场景，各策略使用同一份输入和校验值。策略自己若使用随机搜索或学习，还需单独控制并记录算法随机种子、重置有状态的策略；本入口的任务种子不自动控制算法的随机性。

## 3. 失败和未完成记录

result新增diagnostics，页面结果表上方显示简要信息，并可下载完整JSON。

| 字段 | 含义 |
|---|---|
| planning_failures | 每次规划失败的时刻、车辆、订单、失败阶段和反馈原因 |
| planning_failure_by_leg | 按取货pickup、交付delivery、返回return分别计数 |
| unfinished_tasks | 未完成订单：尚未释放、等待派单、正在执行 |
| vehicles_away_from_home | 执行截止时尚未返回专属停车位的车辆 |
| execution_error | 策略函数异常或非法指派动作；没有则为空 |

同一订单反复尝试可以产生多条失败记录，“10次规划失败”不等于“10个任务无解”。no_route_within_horizon只说明当前预约和时限下没找到该段路线，并不证明物理问题不可行。

等待派单不等于死锁；尚未释放不等于算法忘记处理。记录能帮助定位现象，但不会自动把所有失败归因于拥堵、死锁或任务量过大。策略函数异常标为policy_error，非法动作标为invalid_action；规划器内部非输入类异常仍抛出，避免隐藏程序错误。

独立验证器核对日志计数、任务状态、记录时刻、阶段及返程状态。它不通过重新执行全部搜索来证明每条失败尝试真的无路。
