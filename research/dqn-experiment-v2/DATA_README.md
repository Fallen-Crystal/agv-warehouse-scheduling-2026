# WEPA真实订单数据交付说明

来源：https://github.com/malerinc/slapstack/tree/da6280a8f8be1010eae64264c69a90258a288173，许可见LICENSE。原始订单与初始库存SHA-256已与实验登记值核对。

## 完整原始数据

raw/2_orders.json保留原始字节，共411,830条托盘级订单；字段依次为类型、SKU、绝对秒、码头、批次、周编号。
raw/3_initial_fill_lvl.json为起始库存；raw/1_layout.csv为来源仓库地图。本实验使用课程仿真地图，并未使用该原厂地图。

作者说明订单覆盖89天。按时间戳实算：首笔86466秒，末笔7657200秒，跨越87.624236天；涉及day1至day88，共88个自然日索引，其中88天有订单。相对日索引不能直接换算成日历日期。

## 每天有多少分钟订单

每天时间桶为1440分钟，但订单是离散到达事件，不是每分钟都有一条。
daily_statistics.csv逐日列出订单量、入出库量、实际有订单的分钟数、首末订单时刻和首末跨度。
active_order_minutes统计当天至少出现一笔订单的不同分钟数；first_to_last_minutes包括中间无订单间隔，不表示连续繁忙时间。首末日可能只有部分时间范围；缺少订单不能单独证明停工或缺失记录。

## 本次DQN实际用量

本次只用了4个15分钟训练窗口和1个15分钟监测窗口：共75分钟不同时间片，其中训练60分钟，监测15分钟，合计251条不同源订单。
experiment_windows.csv列出窗口起点、日索引与订单数；experiment_orders.csv提供这些源订单的可读表。
每个seed将同样4个训练窗口重复6轮，不增加真实数据覆盖。3个seed也不代表3组新日期。
监测窗口被反复使用，属于探索性评估，不是未接触的最终测试集。

导出脚本：export_wepa_data.py。summary.json保存机器可读统计；所有实验窗口源行已逐项与原始订单核验。
