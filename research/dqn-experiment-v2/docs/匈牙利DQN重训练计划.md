# 匈牙利与GA双动作DQN重训练协议

本轮目标是在未见订单上，由DQN独立决定使用匈牙利或GA，使正式F低于固定GA、原精准匹配和固定匈牙利。是否达成以冻结模型的最终测试为准，不以训练损失或训练集成绩代替。

## 固定条件

- 正式F：0.5T/900 + 0.3R/900 + 0.2D/5400，越小越好。
- 62×47仓库、6台AGV、5层、1格/秒和SIPP物理执行规则保持一致。
- GA预算：proxy=192、previews=6、generations=16、gate=False；沿用原计划缓存。
- 动作0明确采用现有 `matching_hungarian` 的F局部代理版本；动作1为原joint GA。匈牙利局部代理不是全时域最优保证，也不能把改成本矩阵后的差异归功于匈牙利算法本身。
- 原精准匹配基线保留原最大匹配数、最小估计代价的精确DP及其提交顺序。

五个最终测试日期分别有55、144、85、89、94条订单；日期55为60分钟，其余为30分钟。不同方法只在相同日期、相同完整输入和相同物理seed内比较，并以配对相对F的平均值汇总。绝不将长短窗口的绝对F差异解释成性能提升。

候选窗口仅按原始输入筛选：40～240条订单，包含出入库，1～5种SKU，所选SKU初始库存总和不超过900，每个库存前缀均在0与该SKU初始库存+50之间。有合格整点小时的未用日期优先取最早一小时，否则取最早完整半小时。不拆分同时间订单批次，不按算法成绩挑测试日期。

独立输入审计已验证2298条源订单、完整半开窗口、源行无重叠、完整日期隔离、初始库存和逐笔容量前缀，以及191个冻结基线文件。

## 学习方法

从零初始化，不加载原动作0属于精准匹配的网络、经验池、目标网络或Adam状态。新网络为32-64-2 ReLU Double DQN，gamma=1，学习率0.0003，小输出初始化0.01。首批六轮，每轮重新打乱十个训练日期，探索率依轮次从0.40下降到约0.077。

新状态仅使用已发布订单、当前AGV与已提交计划。保留原状态信息，将积压量和时刻改为平滑有界表示，避免高积压状态被同一截断值掩盖；新增当前就绪订单ETA统计，不读取未来订单，不为选动作额外试跑GA。使用5步回报，每个新决策执行4次经验回放更新；终局清空多步队列。奖励仍是物理成本Phi差值，终局累计奖励必须等于-F。

每个训练窗口提交完整检查点、随机源、Adam、经验池和奖励总账，允许中断后精确续跑。每轮在四个验证日期冻结推断，逐项检查网络、目标网络、优化器、经验池和随机源没有改变。

验证规则：分别计算DQN相对三种基线的平均配对F比值，以其中最差的比值最小者选优。保存best和latest，不能根据最终测试成绩选检查点。首批训练完成后先检查验证曲线，再决定是否追加简单改进；测试命令需要完整训练完成标记，提前执行会拒绝。

原四个验证日期的纯GA结果在旧代码、输入和完整记录审计通过后复用，避免无意义地重做同一个昂贵实验。原精准匹配与固定匈牙利使用新执行器运行；最终测试的四种策略全部在对应新订单上执行。

训练前的7项检查已通过，覆盖5步回报和终局屏蔽、模型恢复后精确继续更新、32维物理桥接、冻结推断、匈牙利与独立穷举，以及原约束检查。桥接检查用少量已用训练订单，只作程序验证，不作为成绩。

六轮训练与验证已启动，最终测试尚未开启。现阶段没有新模型优于三基线的结论。若验证未改善，将只基于训练和验证迭代；如果最终测试没有同时改善，报告必须如实记录。五个日期与单个固定随机seed只能提供有限证据，输入是源订单与合成货架位置的映射，不能直接宣称在原工厂或全部未知订单上保证获益。
