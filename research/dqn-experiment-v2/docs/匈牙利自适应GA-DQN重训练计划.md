# 匈牙利与双概率自适应GA的DQN重训练协议

本文件对应最新用户要求：GA交叉率和变异率都需要自适应。原版本已有自适应变异率，但交叉基本每次执行，因此停止旧训练并保留记录，新模型、经验池、优化器均从零开始。原实验源码和冻结日期划分保留。

## 自适应规则

每代仅使用当前GA种群的最佳代理分数、连续停滞代数s与联合基因多样性d，不读取未来订单，不增加轨迹预览。

- 联合多样性d=不同的(任务顺序,车辆归属向量)数/种群规模。单任务时也能体现车辆归属差异。
- 顺序变异率pm=clip(0.7×[1+0.20s+0.60(1−d)],0.05,0.95)。
- 车辆归属变异率沿用原关系min(0.95,pm+0.1)，单独记录。
- 交叉率pc=clip(0.9−0.04s−0.20(1−d),0.55,0.95)。
- 停滞或同质化时提高变异、适度降低交叉；出现新最佳时s清零。规则不保证多样性单调增加。

每个子代按pc决定是否交叉；未交叉则完整复制父代，随后独立尝试变异。保留两个精英。交叉/变异的触发不一定产生不同基因，例如父代相同、重采样到原车辆，因此日志操作次数不能当作不同候选数。

种群12、精英2、最多16代、最多192次代理评估、最多6次轨迹预览、gate=False、原计划缓存均保持。192是上限，不强制用满。DQN的GA动作与纯GA基线共享同一实现、种子生成方法与预算，绝不拿旧GA成绩冒充新GA对照。

旧bandit诊断中的inventory_risk使用完整订单数归一化，因此日志会随未来数量变化。当前ActionAdapter忽略这个诊断State，它不进入DQN的32维状态，也不影响本次检查的实际派单。正式平均响应时间R与离线奖励仍使用案例总订单数归一化；该奖励常数不作为网络状态特征。检查针对冻结推断，不据此声称训练奖励只依赖当前可见订单数。

每轮用四个验证日期与三个基线逐日期配对，计算每基线的平均F比值，以三个均值中的最差者最小来选择模型。未见测试仅在完整训练与验证选模后开启。若验证不理想，先在训练/验证范围做简单改进，不用测试反复挑模型。

纯精准匹配、纯匈牙利不调用GA，复用旧版同日期、同物理seed且源代码哈希未变的有效对照，避免重复仿真；纯自适应GA必须重跑。

## 正式目标与记录

F=0.5T/900+0.3R/900+0.2D/5400，越低越好。仓库62×47、6台AGV、5层、1格/秒、SIPP和正式F均不变。T不计最终回家完成时刻，D包括回家距离；奖励总账必须等于−F。

每次GA搜索保存逐代pm、pc、归属变异率、联合多样性、停滞代数和真实操作触发次数。检查点保存网络、目标网络、Adam、经验池和随机源；冻结推断逐项检查这些状态不变。

最终报告同时披露平均配对改善率、每日期胜负、动作次数、完整物理审计和限制。五个日期和一个seed不能支持普遍优越或统计显著的结论；合成货架映射也不能直接代表原工厂部署。

## 长任务完成后的自动收尾

```powershell
python -B post_fit_adaptive_learning.py
```

该入口必须在fit完成后执行；训练未完整结束会直接拒绝，既不运行测试，也不写交付完成状态。先独立审计全部训练、验证和检查点，再保存训练经验上的只读Q值/动作诊断及验证复核结果。诊断不是性能改善证据。

只有选中模型相对三个基线的验证集平均配对改善率均大于1e-8%，才调用既有冻结test入口；否则记录needs_training_improvement，保留未见测试不开启，供下一轮训练改进。最终测试完成后再次独立审计、生成中文报告/CSV，并用独立合成新订单执行冻结推断检查。测试中的负改善原样保留，不据此自动修改模型重跑同一未见测试。final_evaluation_complete仅表示完整评价结束，不等同于性能目标达成。

跨进程等待曾被沙箱拒绝，PowerShell版本又受脚本签名策略限制，均未部署成功。现已部署`watch_adaptive_fit_completion.py`：调用Windows原生目录变更通知，在订阅目录之后检查fit_complete.json，阻塞等待而非定时轮询，不打开训练进程句柄、不改变系统执行策略。真实创建事件烟雾测试已通过；监听器通过独占启动记录避免重复启动，收到标记后执行上述收尾入口，完整性仍由独立审计判断。不得因看到标记就直接宣称训练有效或性能达标。

自动收尾在开启测试前及测试完成后均执行原始订单、库存、划分来源审计；任一来源哈希或重建结果不符即停止。报告发布还必须确认当前best.npz的SHA256与审计选择的checkpoint_sha256一致，防止过期审计绑定另一个当前模型。新增测试覆盖来源初始不符、测试期间来源变化，以及报告模型身份不符时拒绝所有最终输出。这些辅助收尾代码不修改已冻结的训练实现、物理规则或预算。

## 单次决策的计算耗时诊断

```powershell
python -B profile_adaptive_ga_decision.py
```

只读取第一个训练日期的初始状态，强制执行一次GA派单，用cProfile记录函数自身耗时、累计耗时与调用次数；完整数据输出为results/adaptive_ga_first_decision_profile.json及对应.prof。保留正式候选算子、代理与预览预算，使用同一物理执行接口。强制动作和单个状态不用于证明DQN自主选择、正式F改善或整窗吞吐；剖析本身也会增加运行开销。

该诊断不修改已运行的fit，不重复完整窗口，不读取测试成绩。输出仅在整个单次决策成功后写入；因此没有输出只能说明诊断尚未提交结果，不能凭此定位瓶颈。脚本拒绝覆盖已有诊断文件。
