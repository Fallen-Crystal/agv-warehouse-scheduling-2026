# 推荐算法的一条主线

**外部事件发布 → WMS固定合法货位 → 负载门控 → 联合GA搜索 → SIPP完整试排 → 原子提交 → 真实执行与独立验解。**

门控仅在流未关闭且可见待处理数不超过空闲车辆数时启用：用预计服务耗时作边成本，位掩码动态规划求当前最大基数、最小成本批量匹配，再逐项SIPP检查与提交。它不是匈牙利实现，也不是按车辆逐一贪心；只能证明固定边成本的瞬时匹配子问题精确。

有积压或流关闭后，用一个联合GA同时表示任务顺序和车辆归属。无需先做一套分配、再锁死它做顺序优化、再叠加两种修复。软分区由设备上下区域引导：75%选择局部/近车候选池，其余可选全车，允许跨区。

固定预算：种群12、精英2、三元锦标赛选择；订单片段交叉，归属基因按父代选择；顺序交换概率0.7、换车变异概率0.8；最多16代和192个代理估价。代理不计完整交通冲突，只负责排序。每次搜索最多6次当前完整可见任务SIPP预演，包含可行锚点和可能的上一轮候选，不是每代6次，也不是每个染色体都做物理解码。

候选只有在相同已知任务范围内完整可行且同一F严格降低时才替换。若没有有效候选，保留可行锚点；实际SIPP无法提交的任务等待后续事件，不得忽略碰撞强行执行。当前默认不启用匈牙利种子、蚁群、粒子群、复合邻域或额外两车协调器；它们保留作对照。

触发条件：有空车且有可执行任务时决策；新可见任务、流关闭、无旧计划，或完成事件后距上次搜索至少64步且还有多项待处理，触发搜索。已派任务和真实库存不回滚。当前方法没有加入仿真时间中的实时计算延迟；CPU单独报告。

|职责|接口/代码|输入→输出|
|---|---|---|
|数据映射|wepa.data.build|原请求窗口→课程模型、货位初值、任务|
|执行状态|wepa.kernel.World|物理事件、库存、路径、锁、可见任务|
|发布/层序|publish_and_complete / ready|可见单→绑定货位与合法可派单|
|调度|ResearchPolicy.action/search|当前快照→订单顺序、车辆归属/当前批次|
|候选|improved.genetic.candidates|快照与锚点→联合GA候选|
|预测|forecast.snapshot/rollout|仅已发布任务副本→完整可见任务预测指标|
|路径|SafeIntervalRouter / World.trip|合法端点、作业时长、他车预约→逐步路径与服务事件|
|提交|World.commit|通过预约检查的路线→原子更新任务、货位锁和车辆计划|
|验解/评分|wepa.check.validate / objective.checked_score|完整轨迹→合法性与T/R/D/F|

分工可按订单调度和路径规划拆分，但必须共同遵守快照、路线、库存和评分接口；不能由调度用静态曼哈顿距离宣称F下降，路径层再自行改任务或漏计返库。完整源码和版本身份在 current/runtime.zip；current/code-guide仅为可阅读副本。
