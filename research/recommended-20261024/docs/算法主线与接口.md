# 推荐算法主线与模块接口

当前推荐方案 `gate` 的在线调度主线如下：

**外部事件发布 → WMS 确定合法货位 → 低负载门控匹配 → 联合 GA 搜索 → SIPP 完整试排 → 原子提交 → 物理执行与独立验解**

## 核心流程说明

1. **低负载门控（`matching`）**：当订单流尚未关闭且当前可见待处理任务数不超过空闲车辆数时启用。以预计服务耗时作为边权，采用位掩码动态规划精确求解当前批次的最大基数、最小成本指派，随后逐项经 SIPP 校验并提交。
2. **联合 GA 搜索（`genetic`）**：当存在任务积压或订单流关闭后，采用单一联合遗传算法同时编码任务优先顺序与车辆归属，避免分阶段锁死分配。软分区策略按设备区上下区域构建候选池：75% 概率优先从同区与预计较早空闲车辆中提议归属，25% 概率从全车队提议，保留跨区协作能力。
3. **固定搜索预算**：种群规模 12、精英保留 2、三元锦标赛选择；顺序基因采用片段交叉，归属基因按父代遗传；顺序交换变异率 `0.7`、换车变异率 `0.8`；最多进化 16 代、上限 192 次轻量代理估价（用于快速排序）。每次决策对排名靠前的候选（含可行锚点与上一轮继承计划）执行至多 6 次完整可见任务 SIPP 预演。
4. **严格接纳与回退**：候选方案仅在相同已知任务集合下完整可行且线性目标 `F` 严格降低时替换锚点；若无更优可行候选则保留锚点方案。单次无法无碰撞提交的任务自动留待后续事件触发时重试。匈牙利种子、蚁群、粒子群、复合邻域与局部两车协调器作为研究对照模块保留，默认主线保持精简清晰。
5. **重规划触发条件**：存在空闲车辆且有可执行任务时进入决策；当有新可见任务到达、订单流关闭、尚无有效缓存计划，或任务完成事件距上次搜索达到 64 步且仍有多个待处理任务时，启动新一轮搜索。已派发任务与真实库存状态保持单调推进，累计 CPU 时间独立记录报告。

## 模块接口映射

| 职责 | 模块 / 接口 | 输入 → 输出 |
|---|---|---|
| 数据映射 | `wepa.data.build` | 原始请求窗口 → 仿真地图、初始货位与任务流 |
| 执行状态 | `wepa.kernel.World` | 物理事件、实时库存、车辆轨迹、货架锁与可见任务 |
| 发布与层序 | `publish_and_complete` / `ready` | 可见订单 → 绑定货位与满足层序的可派任务 |
| 调度策略 | `ResearchPolicy.action` / `search` | 当前状态快照 → 订单优先顺序、车辆归属或当前批次 |
| 候选生成 | `improved.genetic.candidates` | 快照与锚点 → 联合 GA 候选编码集合 |
| 滚动预测 | `forecast.snapshot` / `rollout` | 仅含已发布任务的只读副本 → 完整可见任务预测指标 |
| 路径规划 | `SafeIntervalRouter` / `World.trip` | 合法起终点、装卸时长、他车预约表 → 无碰撞逐步路径与服务事件 |
| 原子提交 | `World.commit` | 通过预约校验的路线 → 原子更新任务状态、货架锁与车辆计划 |
| 验解与评分 | `wepa.check.validate` / `objective.checked_score` | 完整执行轨迹 → 合法性校验与 `T/R/D/F` 评分 |

调度层与路径层通过上述快照、路线、库存与评分接口协同解耦：所有候选方案均以真实 SIPP 预演和统一 `checked_score` 评分口径为准。自 2026-11-02 起，`current/run.py` 直接加载 [current/code-guide/improved](../current/code-guide/improved) 中的可读版主线模块运行，冻结基线依赖位于 `current/runtime.zip`。
