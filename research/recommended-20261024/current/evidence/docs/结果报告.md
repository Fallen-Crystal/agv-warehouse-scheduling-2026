# 匈牙利、联合GA与混合初始化：配对比较

本轮完成12次开发、24次验证，共36次主运行。算法、预算及输入在运行前冻结，验证没有调参。仓库规则、真实请求、评价公式和SIPP后端均保持相同。

开发预先选定：**原联合GA＋SIPP**。按预定采用规则，本轮默认：**原联合GA＋SIPP**。

## 三组实际做了什么

|组别|订单调度|路径及物理检查|
|---|---|---|
|gate|当前原方案：低负载精确批量匹配；其他时刻联合GA搜索车辆归属和顺序|原SIPP及预约表|
|hungarian|每个决策点做F感知瞬时匹配；最大匹配数量优先；枚举完工阈值后用匈牙利优化加性成本|原SIPP验证后提交|
|hga|保留gate的低负载支路；将最多2个完整匈牙利种子放入联合GA，替换部分随机个体|与gate相同的完整SIPP预演和实际后端|

匈牙利种子采用两种分轮匹配：预计耗时、瞬时F估计。分轮更新虚拟车辆可用时刻、位置及货架锁；任务数可以超过车数。种子与锚点、其他种子去重，可能少于2个。GA继续允许换车、换序及跨区接单，未将车辆归属锁死，也未在GA每一代重新运行匈牙利。

两个GA组均种群12、最多16代、192次代理评分、6次完整SIPP预演。匈牙利种子不额外调用SIPP；额外匹配计算计入CPU。实际代理评分数会因重复个体不同而变化。纯匈牙利按自身需要运行，不人为消耗同等预算。每窗口CPU上限600秒、墙钟900秒，2个隔离进程。

## 匹配成本与F的关系

统一F=0.5T/900+0.3R/900+0.2D/5400。T为最后订单完成时刻；R为平均发布到完成；D包含所有移动、待命重定位和最终返库。固定大型62×47、6车、5层、1格/秒。F可以超过1，新窗口的绝对F不能与上一轮不同窗口直接比较。P90、空驶和交通等待同步保存，不额外添加权重。

本轮纯匈牙利不只是最小化总路程：先求最大可匹配数，再枚举固定边预测的完工阈值，在阈值内最小化R和D的加性近似，最后比较含T的瞬时成本。这能精确求解该估计问题；车辆相互阻塞、未选择订单的后续顺序及未知请求仍不在这一轮矩阵内。已有累计等待作为常数，不因当前只选部分任务就重复惩罚较老订单。所有实际执行仍由SIPP和独立验解器约束。

混合组只更换初始个体的来源，未额外加一次最终匈牙利重分配。若种子改善个例但总体不稳定，只能说明这套初始化及预算组合尚未稳定胜出，不能宣称所有匈牙利与GA混合方式都无效。
