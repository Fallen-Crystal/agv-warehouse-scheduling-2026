# 匈牙利、联合GA、匈牙利初始化联合GA的固定比较

在运行前固定：大型62×47地图、6辆同构车、5层、900秒来源请求窗口；原有WMS、取放层序、四邻接、碰撞、待命及最终返库规则全部不变。

评价：F=0.5T/900+0.3R/900+0.2D/5400。T为最后订单完成，R为平均发布至完成，D包括待命移动和最终返库。其他算法不进入公式分母。

三组：

1. gate：原有联合GA＋SIPP。原低负载动态规划精确匹配支路保留；其他场景同时搜索车辆归属、任务顺序。种群12、16代、最多192次代理评分、6次完整SIPP预演。
2. hungarian：滚动匈牙利＋SIPP。对当前空闲车和当前可执行任务构建预计耗时/距离表，最大匹配数量优先。在固定边代价下，枚举完工阈值，用匈牙利优化R和D的加性残差，再比较含T的瞬时F估计。只优化当前批次，不能视作全周期F最优。已有等待是常数，选择任务时不重复惩罚等待较久的订单。匹配后依次由原SIPP验证与提交，不能执行的组合跳过并在后续决策点重试。
3. hga：匈牙利初始化联合GA＋SIPP。原即时匹配支路与gate完全相同，隔离初始化作用。用两种虚拟分轮匹配（耗时、F估计）生成最多2个完整种子，替换GA的2个随机初始个体；保留原锚点及其余随机个体。仍同时优化归属和顺序，不锁死分配，不改遗传算子、代数、代理评分或预演上限。生成种子不增加SIPP预演，但计算时间计入CPU。

虚拟种子仅访问当前已发布、未分配任务及锚点预演的WMS货位和层序依赖；它只产生候选，不修改真实库存、绑定、车辆路线。仅SIPP完整预演可接纳候选。

预算公平性：两个GA组均192次代理评分/6次完整预演/16代；匈牙利种子中的匹配工作另行记录并计入CPU。纯匈牙利不用GA，按自身所需计算，不人为消耗同等预算。所有组单窗口CPU600秒、墙钟900秒、两隔离进程。

开发4个已用日期窗口，每组种子0共12次。验证按之前资格，排除所有交付协议已使用窗口和开发日期，依时间顺序挑选4个不同来源日期的新窗口，每组种子0、1共24次。日期已在此前其他窗口使用，不称新日期外部验证。输入清单在任何策略运行前冻结；代码在开发前冻结，验证不调参。开发平均F最低者预先选定，只有验证平均配对F也改善且全部有效才替换默认，否则保持gate。

按来源日期分析，重复种子不是独立场景。报告F、T/R/D、P90、空驶、等待、CPU及逐日期/种子配对结果。必须保留退化、超时和非法结果。全部轨迹独立重验；开发gate与上轮完整轨迹应一致。另做小型枚举、未发布订单不可见、重复执行和预算约束测试。微型最优参照若使用，只作机制回归，不算真实请求验证收益。
