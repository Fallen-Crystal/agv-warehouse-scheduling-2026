# F 综合优化研究结果与运行说明（2026-10-22）

本阶段在旧相对归一化目标下探索了单项/双项/三项搜索代理与多候选组合搜索（`portfolio`），验证了平均订单响应时间 `R` 与总行驶里程 `D` 共同纳入目标的合理性，并完整保留了两轮正式实验的正负对照结果。

## 目标函数

本阶段采用旧版相对归一化目标：`F = 0.5*T/Tref + 0.3*R/Rref + 0.2*D/Dref`（越低越好）：

- `T`：最后一单卸货完成时刻；`R`：订单释放到卸货完成的平均耗时；`D`：全部移动格数（含最终返库）。
- `E = 0.05*D` 作为能耗估算辅助展示项，避免与 `D` 重复加权。
- 同一场景下各算法共用固定参考基准 `(Tref, Rref, Dref)`；在线策略仅观测当前已释放订单。
- 仓库规则保持四邻接、同构 1–10 辆车、货架层序、交付口禁穿行、批次间安全待命与最终返库等全部硬约束。
- 权重 `0.5 / 0.3 / 0.2` 为项目统一设定的综合偏好；关于文献调研、指标尺度、边际权衡及 72 场景权重敏感性分析，详见 [目标函数与论文核对.md](目标函数与论文核对.md)（例如 `T` 不变时，`R` 减少参考值的 1% 等价于 `D` 增加参考值的 1.5%）。

## 第一轮：单项 / 双项 / 三项代理搜索对比

开发集包含 12 场景、14 种策略、共 168 次执行（4 车、8 层，静态 12 单 / 动态 8 单，2 种地图 × 3 个开发种子），仅调整代理搜索方向与匹配方式，候选预演与正式评价保持原目标 F。

| 搜索代理方向 | 开发集相对 v1 的平均 F 改善 |
|---|---:|
| ga_T | 0.526% |
| ga_R | 0.689% |
| ga_D | 0.614% |
| ga_TR | 1.097% |
| ga_TD | 0.208% |
| ga_RD | 1.644% |
| ga_TRD | 0.367% |
| ga_nomat | 1.039% |
| ga_uncal | 0.066% |
| random | 0.117% |
| hybrid | 0.964% |
| matching | -10.196% |

选取开发集排名靠前的 `ga_RD` 与 `ga_TR` 固定配置，在 48 个新场景（4 种地图 × 静态/动态 × 6 个新场景种子）上正式验证（新方法每场景 3 个算法种子，共 384 次执行，全部通过独立验解）：

| 方案 | 新场景平均 F 改善（相对 v1） | 95% 场景种子聚类区间 | 改善 / 退化 / 相同场景 |
|---|---:|---:|---:|
| ga_RD | -0.524% | [-1.168%, 0.151%] | 17 / 30 / 1 |
| ga_TR | 0.271% | [-0.264%, 0.833%] | 21 / 19 / 8 |

结果表明：`ga_RD` 在新场景整体退化，`ga_TR` 均值略升但区间跨零，单靠替换代理方向在开发集上的局部收益未能稳定迁移到新场景，因此两者均保留为对照结果。另 `matching` 控制组采用 FIFO 先选订单，其负差异体现了订单排序与匹配耦合的综合效应。

## 第二轮：多方向候选组合搜索（`portfolio`）

`portfolio` 保留 `v1` 的三个基础候选，并补充 `TR` / `RD` 批次匹配候选，去重后最多对 9 个候选执行真实 SIPP 影子预演并按同一 F 择优（通过扩充候选集合提高解质量，相应增加了计算开销）。

先在 12 个新开发场景（种子 5100–5102，36 次执行）取得 `1.057%` 平均 F 改善，随后冻结配置在 48 个正式测试场景（种子 7100–7105，240 次执行）完成配对验证（场景内先对 3 个算法种子取均值，全部通过独立验解）：

| 正式比较 | 平均逐场景 F 改善 | 95% 聚类区间 | 改善 / 退化 / 相同场景 | 平均逐场景 CPU 比值 |
|---|---:|---:|---:|---:|
| portfolio / v1 | 1.059% | [0.467%, 1.803%] | 24 / 4 / 20 | 1.994 倍 |
| portfolio / greedy | 7.952% | [6.321%, 9.739%] | 42 / 6 / 0 | 9.074 倍 |

| 指标（同一组 48 场景） | v1 场景均值 | portfolio 场景均值 |
|---|---:|---:|
| F | 0.930 | 0.920 |
| T（步） | 266.812 | 264.347 |
| R（步） | 166.152 | 163.644 |
| D（格） | 1122.208 | 1107.819 |
| T/Tref | 0.859 | 0.853 |
| R/Rref | 1.032 | 1.017 |
| D/Dref | 0.955 | 0.944 |
| 求解 CPU 秒数 | 7.976 | 15.488 |
| 场景 P90 订单耗时 | 257.312 | 254.521 |

F 收益按指标拆解（百分点）：`T` 项贡献 `0.351`，`R` 项贡献 `0.477`，`D` 项贡献 `0.231`，合计 `1.059%`，三项指标同步改善。

本报告以“逐场景相对改善再平均”为主要汇总口径（CPU 比值同理，仅计求解阶段，不含离线基准计算与独立验解）。两轮正式实验 624 次、开发 204 次、先导 28 次、小规模与压力测试 28 次，累计 884 次运行；统计区间基于 6 个场景种子聚类自助抽样给出，反映当前仿真生成器分布下的配对稳定性。

## 小规模最优参照

单车静态实例通过 Held–Karp 动态规划求得精确最优；双车 3 单的 8 个参照实例通过穷举指派/排序松弛下界与合法 SIPP 轨迹相等获得最优证书：

- 第一轮 `ga_RD` 命中 `5/8`，`ga_TR` 命中 `6/8`；
- 第二轮 `portfolio` 命中全部 `8/8` 已知最优值，并通过 2 例 10 车 12 动态单、8 层、单交付口的高密度压力测试；
- 参照集中存在最优值为 `F ≈ 0.984` 的实例，说明相对目标值受场景结构与基准表现影响，宜按场景配对评估。

## 运行入口与工程核验

完整源码与算法文档归档于 `../archives/Selected_20261022_source_and_evidence.tar.gz`，解压后核心入口为 `scripts/run_f_research.py`：

```powershell
$env:PYTHONPATH = "$PWD/src"
python -B scripts/run_f_research.py --method portfolio --size medium --mode dynamic --tasks 8 --seed 7100 --optimizer-seed 0 --output runs/my-example.json
python -B -m agv.experiments.f_benchmark --phase final --seed-start 7100 --variants greedy,v1,portfolio --optimizer-seeds 0,1,2 --output runs/my-confirmation --workers 3
python -B results/f-study-20261022/summarize_f.py runs/my-confirmation
```

注：本轮 benchmark 未对 `portfolio` 的 `proxy_evaluations` 字段插桩（记录值 `0` 表示未插桩），实际计算预算以 `candidate_rollouts` 与求解 CPU 秒数衡量。原有 102 份生产源文件逐字节保持不变；358 项标准测试、Ruff 静态检查、183 个文件格式检查、架构检查与 8 项网页契约检查均已通过。

后续研究据此转向固定 F 下的订单–车辆联合重分配、多车路径局部重规划与等预算消融实验。
