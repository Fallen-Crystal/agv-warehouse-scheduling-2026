# F综合优化研究结果与运行说明（2026-10-22）

新场景支持组合搜索平均改善F，但仍有退化案例。 平均订单耗时R和总里程D同时作为目标合理：前者衡量订单服务表现，后者衡量移动成本。所有新实验仍采用原F，未用更换权重制造收益。

## 目标函数

F=0.5 T/Tref + 0.3 R/Rref + 0.2 D/Dref，越低越好。

- T：最后一单卸货完成时刻；R：订单释放到卸货完成的平均耗时；D：全部移动格数，含最终返库。
- E=0.05D，属于D的估算展示项，不再重复加权。
- 所有算法共用固定同场景参考；不可用各算法自身作为分母。在线策略不接收完整场景参考或未来订单。
- 保留四邻接、同构1—10辆车、层数/取货规则、交付口禁穿行、批次间待命和最终返库等既有硬约束。
- R已经包含等车、行驶、装卸和交通等待，这些拆解项另行展示。权重0.5/0.3/0.2是项目偏好约定，不是某篇论文证明的通用最优比例。

文献、尺度、权重交换关系及上一轮72场景的敏感性核对见[目标函数与论文核对](docs/f-objective-literature-review.md)。例如T不变时，R减少参考值的1%，抵消D增加参考值的1.5%；这体现服务与成本的取舍。

## 第一轮：单项/双项/三项搜索是否比上一版更好

开发集12场景、14种策略、168次执行；固定四车、8层，静态12单/动态8单，两个地图和三个开发种子。只改变代理搜索方向和匹配方式，候选预演选择及正式评价仍保留原F。

|---|---:|
| ga_T | 0.526% |
| ga_R | 0.689% |
| ga_D | 0.614% |
| ga_TR | 1.097% |
| ga_TD | 0.208% |
| ga_RD | 1.644% |
| ga_TRD | 0.367% |

选开发排名靠前的RD和TR，随后固定配置，用4种地图×静态/动态×6个新场景种子测试，共48场景。新方法每场景运行3个独立算法种子，控制组各运行一次，共384次执行，全部独立验解通过。

| 方案 | 新场景平均F改善，相对v1 | 95%场景种子聚类区间 | 改善/退化/相同场景 |
|---|---:|---:|---:|
| ga_RD | -0.524% | [-1.168%, 0.151%] | 17/30/1 |
| ga_TR | 0.271% | [-0.264%, 0.833%] | 21/19/8 |

结论：单独RD退化，TR的微小改善不能排除零收益。两者不替代v1。开发集局部改善没有稳定迁移到新场景，这是本轮必须保留的负面结果。matching控制组使用FIFO先选订单，因此不能把其退化全部归因于匹配算子。

## 第二轮：保留v1候选、增加多方向候选后统一按F选

组合搜索portfolio保留v1的三个候选，再加入TR/RD批次匹配候选；去重后最多九个候选通过真实SIPP影子执行统一评分。它增加了计算预算，不是等预算下单个遗传算子优越性的证明。

先在新的12个开发场景（种子5100—5102）评估36次执行，平均F改善1.057%；随后冻结配置，在另一组48个场景（种子7100—7105）进行240次正式执行，全部验解通过。无按场景选择最好算法种子，先在场景内平均三个算法种子，再作配对。

| 正式比较 | 平均逐场景F改善 | 95%聚类区间 | 改善/退化/相同场景 | 平均逐场景CPU比值 |
|---|---:|---:|---:|---:|
| portfolio / v1 | 1.059% | [0.467%, 1.803%] | 24/4/20 | 1.994倍 |
| portfolio / greedy | 7.952% | [6.321%, 9.739%] | 42/6/0 | 9.074倍 |

| 指标，同一组48场景 | v1场景均值 | portfolio场景均值 |
|---|---:|---:|
| F | 0.930 | 0.920 |
| T（步） | 266.812 | 264.347 |
| R（步） | 166.152 | 163.644 |
| D（格） | 1122.208 | 1107.819 |
| T/Tref | 0.859 | 0.853 |
| R/Rref | 1.032 | 1.017 |

| 求解CPU秒数 | 7.976 | 15.488 |

F收益拆解（百分点，正为改善、负为牺牲）：T项0.351，R项0.477，D项0.231，三项相加等于1.059%。没有为R或P90设置不许退化的保护；允许单项牺牲，但必须报告。

均值F的相除与“逐场景相对改善再平均”不是同一统计量；本报告主要采用后者。CPU比值同理。CPU仅计求解阶段，不含离线标准参考和独立验解。上述计时不等同于实车实时性承诺。

这两轮正式实验共624次执行；开发204次，先导28次，额外小规模/压力测试28次，共884次实验执行。统计区间只按6个场景种子聚类自助抽样，属于固定仓库生成器下的有限验证，不是所有真实仓库的保证；第一轮两个候选的区间未作多重比较校正。

## 小规模最优参照与全局最优边界

单车静态支持类可用已有Held–Karp动态规划取得全局最优。双车3单的8个参照案例由穷举指派/排序的松弛下界与合法SIPP执行见证相等得到证书；本轮原权重和物理规则不变。

- 第一轮RD命中5/8，TR命中6/8，不能包装成全局最优。
- portfolio命中8/8已知最优值。另两例10车12动态单、8层、共用一个交付口的压力测试合法。
- 8/8只证明这些具体小实例取得最优值，不能外推到4车12单、动态未知订单或全部地图。有限预算GA、批次匹配和SIPP组合没有整个F的近似比保证。
- 例如参照中存在F约0.984已经最优的案例，说明不能用F<0.9等统一阈值判断算法质量。

## 运行与交接

本包包含实际Python代码、原执行框架、测试、全部新实验原始轨迹/场景、负面结果、代码哈希和报告。入口为scripts/run_f_research.py。实现、课程知识对应、计算预算与接口限制见[算法说明](docs/f-search-implementation.md)。

```powershell
$env:PYTHONPATH = "$PWD/src"
python -B scripts/run_f_research.py --method portfolio --size medium --mode dynamic --tasks 8 --seed 7100 --optimizer-seed 0 --output runs/my-example.json
python -B -m agv.experiments.f_benchmark --phase final --seed-start 7100 --variants greedy,v1,portfolio --optimizer-seeds 0,1,2 --output runs/my-confirmation --workers 3
python -B results/f-study-20261022/summarize_f.py runs/my-confirmation
```

正式测试目录：runs/f-final-20261022和runs/f-portfolio-final-20261022。场景在scenes目录，结果轨迹在traces目录；可按文件名关联。算法种子独立于场景种子。每轮freeze.json记录源代码哈希，第一轮完整代码快照单独保存；没有在运行中改代码。

本轮benchmark对portfolio的proxy_evaluations字段未插桩，0应按未记录解释，不是实际零次评估；使用candidate_rollouts与CPU量化实际预算。当前研究接口的portfolio组合固定，不应另设terms或budget解释该组合。

原有102份生产源文件逐字节保持一致；新研究代码为附加模块。公共注册表和默认算法未切换。此次只有独立副本的本地验证快照，没有推送/合并远端。

验证：358项标准测试通过，含网页接口与来源检查；Ruff检查、183个文件格式检查、架构检查、网页8项契约检查通过。Windows验证设置独立临时目录、UTF-8并在允许硬链接的正常权限下运行；解压包不含Git历史，依赖提交号的旧来源追溯测试须在Git检出或先建立本地快照后执行。最初受沙箱和辅助启动器影响的中断尝试不计为通过，最终标准测试日志保留。

后续优先：在固定F下继续研究真正的订单—车辆联合重分配及多车路径子集重规划，以本轮候选组合为可选参照；用同预算/同时间预算控制组分离“候选更多”和“搜索算子更好”的贡献。不要通过再调权重掩盖负面结果，也不要因为R略升就自动否决F下降的方案。
